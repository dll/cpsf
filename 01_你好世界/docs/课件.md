## 📖 教学内容

### 一、导入：为什么从 Hello World 开始？（5分钟）

#### 1.1 一个经典的传统

几乎每一本编程教材、每一门编程语言课程，第一个程序都是打印 "Hello, World!"。

这个传统起源于 1978 年 Brian Kernighan 和 Dennis Ritchie 的《C程序设计语言》。从那以后，它成了程序员与一门新语言"打招呼"的仪式。

#### 1.2 但我们的 Hello World 不一样

普通的 Hello World 只是入门，**我们的 Hello World 是起点**。

> 💡 **思考**：这一行代码 `printf("Hello, Plugin Framework!")` 里，已经藏着软件框架的种子。你能看出来吗？

带着这个问题，我们开始第一阶段的学习。

### 二、传统讲授：C程序的基本结构（15分钟）

#### 2.1 代码全貌

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, Plugin Framework!\n");
    return 0;
}
```

虽然只有短短几行，但每一行都值得深究。

#### 2.2 逐行解读

| 代码 | 含义 |
|:---|:---|
| `#include <stdio.h>` | 引入标准输入输出头文件。告诉编译器：我要使用标准库中的输入输出函数。 |
| `int main(void)` | 主函数声明。`int` 表示返回整数，`main` 是函数名，`void` 表示不接收参数。**所有C程序都从这里开始执行。** |
| `printf("...");` | 调用标准库函数 printf，在屏幕上打印字符串。`\n` 是换行符。 |
| `return 0;` | 函数返回值。返回 0 表示"程序正常结束"，返回非0表示出错。 |

#### 2.3 编译运行流程

当你输入 `gcc hello.c -o hello.exe` 时，背后发生了什么？

```
源代码 hello.c
    ↓ 预处理（Preprocessing）
    展开#include、#define等宏
    ↓ 编译（Compilation）
    翻译成汇编代码
    ↓ 汇编（Assembly）
    生成目标文件 hello.o
    ↓ 链接（Linking）
    把printf的实现"接"进来 → hello.exe
```

> 🎯 **关键洞察**：你写的代码里并没有 `printf` 的实现，但程序却能运行它。这是因为**链接器**把标准库里的 printf 函数和你的代码"拼"在了一起。
>
> 这就是最朴素的"复用"思想——**用别人写好的代码，做自己的事情**。

### 三、AI化辅助：用AI探索编译奥秘（15分钟）

#### 3.1 AI演示：深入理解编译过程

**Prompt 示例**：

```
我是一名大三学生，正在学习C语言。请用通俗的语言解释：
当我执行 gcc hello.c -o hello.exe 时，
预处理、编译、汇编、链接这四个阶段分别做了什么？
请用"工厂流水线"的比喻来解释。
```

**AI输出（示例）**：

> 可以把C程序编译想象成一条"食品加工厂流水线"：
>
> 1. **预处理（洗菜备料）**：把 #include 的头文件"抄"进来，把宏定义替换掉。就像做菜前先把食材洗好、切好。
>
> 2. **编译（烹饪）**：把C代码翻译成汇编语言（人类能读懂的低级语言）。就像厨师按照食谱把食材做成菜。
>
> 3. **组装盘（装盘）**：把汇编代码翻译成机器码（0和1），生成目标文件。就像把菜装进盘子里。
>
> 4. **链接（送餐桌）**：把你的代码和 printf 等库函数"拼"在一起，生成可执行文件。就像把多道菜端到餐桌上，组成一顿完整的饭。

#### 3.2 核验练习：AI 说的对吗？

**任务**：用 `gcc -E hello.c -o hello.i` 查看预处理后的结果，验证 AI 说的"头文件被抄进来"是否正确。

```bash
gcc -E hello.c -o hello.i   # 只做预处理，输出到 hello.i
notepad hello.i              # 打开看看
```

> 📝 **AI核验记录**
> - Prompt：（上面的Prompt）
> - AI输出：（上面的解释）
> - 人工核验：通过 `gcc -E` 命令验证了预处理阶段确实展开了头文件
> - 修正/补充：实际的 stdio.h 内容比想象中复杂得多，有很多宏定义和函数声明

#### 3.3 拓展思考：如果没有标准库呢？

**提问**：如果C语言没有提供 printf，我们怎么在屏幕上打印文字？

> 💡 这是一个重要的架构问题。现在你用的是别人提供的"接口"（printf），如果这个接口不存在，你就得自己和操作系统打交道……
>
> 这正是我们后续阶段要解决的问题——**如何设计好的接口，让复杂的事情变得简单**。

### 四、做中学：动手实验（10分钟）

#### 实验1：修改输出内容

**任务**：把 "Hello, Plugin Framework!" 改成你自己的名字，重新编译运行。

```c
printf("你好，我是XXX！\n");
```

**观察**：修改源码 → 重新编译 → 运行，这个过程你做了几次？

#### 实验2：故意制造错误

**任务**：把 `#include <stdio.h>` 删掉，编译看看会报什么错。

```bash
gcc hello.c -o hello.exe
# 会报什么错误？你能看懂吗？
```

**思考**：编译器的错误信息在告诉你什么？为什么没有 include 就不能用 printf？

#### 实验3：多个 printf

**任务**：写三行 printf，打印三行不同的文字。

```c
printf("第一行\n");
printf("第二行\n");
printf("第三行\n");
```

**观察**：执行顺序是怎样的？和代码书写顺序一致吗？

## 🔄 进化视角

### 本阶段的"种子"

虽然我们现在只有一个简单的 `printf`，但这里面已经藏着软件架构的核心思想：

| 种子 | 对应未来的概念 |
|:---|:---|
| 调用别人写好的函数（printf） | **接口** —— 定义"怎么用"，隐藏"怎么实现" |
| 编译器把代码转成可执行文件 | **编译与链接** —— 从源码到运行的桥梁 |
| 标准库提供通用功能 | **库** —— 复用的基本单位 |
| main函数是固定的入口点 | **框架的控制反转** —— 你写的代码被框架调用 |

### 本阶段的痛点

```
😫 所有代码都写在一个文件里
   代码多了之后，维护起来会很痛苦
```
