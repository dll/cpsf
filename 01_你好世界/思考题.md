## 🤔 第1题：编译与解释

**问题：**

我们学了C语言的"编译"——把源代码全部翻译成机器码，生成可执行文件。

但是你可能也听说过，Python、JavaScript 这些语言是"解释型"的——不需要编译，直接一行一行解释执行。

请你思考：
1. 编译型语言和解释型语言，各有什么优缺点？
2. 为什么 C 语言选择了编译型，而 Python 选择了解释型？
3. 有没有"半编译半解释"的语言？如果有，它是怎么工作的？
4. 我们后面要学的"插件框架"，和"解释/编译"有什么关系？（提示：插件是运行时加载的）

## 🤔 第2题：链接的代价

**问题：**

我们学了"链接"——把标准库的 printf 代码拼到我们的程序里。

但是你有没有想过：如果100个程序都要用 printf，那静态链接的话，每个程序的 exe 里都有一份 printf 的代码，内存里不就有100份重复的 printf 吗？这是不是很浪费？

请推演：
1. 静态链接（把代码复制进 exe）有什么优点？有什么缺点？
2. 怎么解决"每个程序都有一份重复代码"的问题？
3. 你觉得"动态链接"（运行时才去 dll 里找函数）可能是怎么解决这个问题的？
4. 动态链接又会带来什么新问题？

（提示：下一阶段会学静态库，下下阶段学动态库，先自己想想看！）

## 🤔 第3题：表达式语言的得与失

**问题：**

C语言被称为"表达式语言"——几乎一切都是表达式，连赋值都是表达式。

有人说这是C语言的优点：灵活、表达力强、代码简洁。
也有人说这是C语言的缺点：太灵活容易出错、代码可读性差、新手容易踩坑。

请你分析：
1. 举一个"赋值是表达式"带来便利的例子
2. 举一个"赋值是表达式"导致bug的例子
3. 编程语言设计中，"灵活"和"安全"是一对矛盾吗？
4. 如果让你来设计一门语言，你会把赋值设计成表达式还是语句？为什么？

### 第1题：编译与解释

- 编译型优点：运行快、独立执行、代码保护好
- 编译型缺点：编译慢、跨平台差（不同CPU要重新编译）
- 解释型优点：开发快、跨平台好、灵活（运行时可以改代码）
- 解释型缺点：运行慢、依赖解释器
- 为什么C用编译型：C是系统级语言，追求性能，直接操控硬件
- 为什么Python用解释型：Python是脚本语言，追求开发效率
- 半编译半解释：Java（编译成字节码，JVM解释执行）、C#（类似）
- 和插件的关系：插件也是运行时才加载的，有点像"解释"的思想——不需要提前把所有代码都编译进去

### 第2题：链接的代价

- 静态链接优点：程序独立，不依赖外部库，运行快
- 静态链接缺点：exe体积大，内存浪费（多个程序各存一份），库升级要重新编译
- 解决方法：动态链接！所有程序共享同一份库代码（在内存里只有一份）
- 动态链接的新问题：
  - 依赖外部dll，缺少了就跑不起来
  - 版本兼容问题（dll地狱）
  - 运行时加载有性能开销

### 第3题：表达式语言的得与失

- 便利的例子：a = b = c = 5 链式赋值；if ((p = malloc(...)) != NULL) 一行搞定分配+判断
- 导致bug的例子：if (a = 5) 把 == 写成 =，结果条件永远为真，bug很难发现
- 灵活和安全确实是矛盾的——越灵活的语言，越容易写出错；越安全的语言，限制越多，写起来越"绑手绑脚"
- 没有标准答案，说说你的理由就好。比如：给新手用的语言，安全更重要；给高手用的系统级语言，灵活更重要

### 第4题：从一行代码看软件架构

- 为什么这么多概念：因为"复用"和"分层"的思想——每一层解决一个问题，每一层都对上一层隐藏细节
- 关系：表达式是最小单元 → 函数调用是表达式的一种 → 函数实现在标准库里 → 头文件提供接口 → 编译把C变成汇编 → 汇编变成机器码 → 链接把库拼进来 → 可执行文件是最终产物
- 接口与实现分离出现了好几次：
  1. 头文件（接口）vs 库文件（实现）
  2. 函数声明（接口）vs 函数定义（实现）
  3. C语言（高级接口）vs 机器码（底层实现）
- 因为软件架构的核心思想就是"分层、封装、复用、接口与实现分离"——这些思想在最基础的printf调用里就已经体现了。理解了这些底层的原理，再去看框架、看架构，就会发现：万变不离其宗。
