## 一、什么是控制结构？

### 1.1 概念

**控制结构**就是控制代码执行顺序的语法。

想象你在开车：
- 🚗 **直行**：一直往前开 —— 对应**顺序结构**
- 🔀 **岔路口**：选左边还是右边 —— 对应**分支结构**
- 🔄 **绕圈**：围着广场转三圈 —— 对应**循环结构**

这三种结构是所有编程语言的基础。无论多么复杂的程序，拆到底都是这三种结构的组合。

### 1.2 为什么需要控制结构？

第1讲的 `printf("Hello");` 只有一行，从上到下执行就完事了。

但现实中的程序是这样的：
- 用户输入不同的数字，要执行不同的操作
- 同样的操作要执行很多次
- 程序不能做完一件事就退出

所以我们需要**控制结构**来组织代码的执行流程。

## 二、顺序结构

### 2.1 概念

**顺序结构**：代码从上到下，一行一行依次执行。

这是最基本、最默认的执行方式。你写的每一行代码，默认都会按顺序执行。

### 2.2 示例：ATM欢迎界面

```c
printf("========================================\n");
printf("       欢迎使用 CCIT ATM 系统\n");
printf("========================================\n");
printf("\n");
```

这四行 `printf` 就是典型的顺序结构：
1. 先打印第一行分隔线
2. 再打印欢迎语
3. 再打印第二行分隔线
4. 最后打印一个空行

一步一步，不跳，不回头。

## 三、分支结构

### 3.1 概念

**分支结构**：根据条件判断，选择走不同的代码路径。

就像走到岔路口——往左走还是往右走，取决于你的判断。

C语言有两种分支语句：
- `if-else`：灵活，适合各种条件判断
- `switch`：简洁，适合"多选一"的场景

### 3.2 if 语句

#### 基本形式

```c
if (条件)
{
    // 条件为真时执行这里
}
```

#### if-else 形式

```c
if (条件)
{
    // 条件为真时执行这里
}
else
{
    // 条件为假时执行这里
}
```

#### 多分支形式

```c
if (条件1)
{
    // 条件1为真
}
else if (条件2)
{
    // 条件2为真
}
else
{
    // 都不满足
}
```

### 3.3 示例：取款的条件判断

```c
if (amount <= 0)
{
    printf("❌ 取款金额必须大于0！\n");
}
else if (amount > balance)
{
    printf("❌ 余额不足！\n");
}
else
{
    balance = balance - amount;
    printf("✅ 取款成功！\n");
}
```

三种情况，三条路径：
1. 金额 ≤ 0 → 报错
2. 金额 > 余额 → 报错（余额不足）
3. 其他情况 → 正常取款

### 3.4 switch 语句

`switch` 适合"根据一个变量的值，从多个选项中选一个"的场景。

```c
switch (choice)
{
    case 1:
        // choice == 1 时执行
        break;
    case 2:
        // choice == 2 时执行
        break;
    case 3:
        // choice == 3 时执行
        break;
    default:
        // 都不匹配时执行
        break;
}
```

### 3.5 示例：ATM菜单选择

```c
switch (choice)
{
    case 1:
        printf("【查询余额】\n");
        printf("余额：%.2f 元\n", balance);
        break;

    case 2:
        printf("【存款业务】\n");
        // ... 存款逻辑
        break;

    case 3:
        printf("【取款业务】\n");
        // ... 取款逻辑
        break;

    case 0:
        printf("再见！\n");
        running = 0;
        break;

    default:
        printf("无效的选择！\n");
        break;
}
```

### 3.6 ⚠️ break 的作用

`break` 的意思是"跳出 switch"。

如果没有 `break`，程序会从匹配的 `case` 开始，**一直往下执行所有后续的 case**，这叫"case 穿透"。

```c
switch (x)
{
    case 1:
        printf("A");  // 没有 break！
    case 2:
        printf("B");
        break;
}
// 如果 x=1，会输出 "AB" —— 穿透了！
```

大多数时候我们不想要穿透，所以每个 `case` 后面都要记得加 `break`。

### 3.7 if vs switch 怎么选？

| 场景 | 推荐 |
|------|------|
| 判断范围（大于、小于） | `if-else` |
| 判断多个条件组合 | `if-else` |
| 根据一个值多选一 | `switch` |
| 选项超过3个 | `switch` 更清晰 |

## 四、循环结构

### 4.1 概念

**循环结构**：让同一段代码重复执行多次。

为什么需要循环？
- 菜单程序：用户操作完一次，回到菜单继续操作
- 打印100次"Hello"：不用写100行 printf
- 遍历数组：一个一个处理每个元素

C语言有三种循环：
- `while`：先判断条件，再执行（适合不知道次数的循环）
- `do-while`：先执行一次，再判断条件
- `for`：适合知道循环次数的场景

### 4.2 while 循环

```c
while (条件)
{
    // 条件为真时，重复执行这里的代码
}
```

执行流程：
1. 判断条件是否为真
2. 如果为真 → 执行大括号里的代码 → 回到第1步
3. 如果为假 → 结束循环

### 4.3 示例：ATM主循环

```c
int running = 1;  // 运行标志

while (running)    // 只要 running 为 1，就一直循环
{
    // 显示菜单
    // 读取用户输入
    // 执行对应的操作
    // ...

    // 如果用户选了"退出"，就把 running 设为 0
    // 循环就结束了
}
```

这是菜单程序的经典写法：
- 用一个变量（`running`）控制循环是否继续
- 用户选"退出"时，把变量设为 0，循环自然结束

### 4.4 for 循环

`for` 循环适合"知道要循环多少次"的场景。

```c
for (初始化; 条件; 更新)
{
    // 循环体
}
```

执行流程：
1. **初始化**（只执行一次）
2. 判断**条件** → 为假就结束
3. 执行循环体
4. **更新**变量
5. 回到第2步

### 4.5 示例：打印3次欢迎语

```c
for (int i = 1; i <= 3; i++)
{
    printf("第 %d 次：欢迎光临！\n", i);
}
```

输出：
```
第 1 次：欢迎光临！
第 2 次：欢迎光临！
第 3 次：欢迎光临！
```

### 4.6 while vs for 怎么选？

| 场景 | 推荐 |
|------|------|
| 不知道循环多少次（菜单、等待用户输入） | `while` |
| 知道循环多少次（遍历N次、计数） | `for` |
| 条件判断是循环的核心 | `while` |
| 计数器是循环的核心 | `for` |

## 五、三种结构的组合

现实中的程序，不是只用一种结构，而是**三种结构嵌套组合**。

看我们的 ATM 程序：

```
main 函数
├── 顺序：变量定义（balance, choice, amount, running）
├── 顺序：打印欢迎界面
└── 循环：while (running)         ← 最外层是循环
    ├── 顺序：显示菜单
    ├── 顺序：读取用户输入
    └── 分支：switch (choice)     ← 循环里面是分支
        ├── case 1：查询余额（顺序）
        ├── case 2：存款（顺序 + if分支）
        ├── case 3：取款（顺序 + if-else分支）
        ├── case 4：转账（顺序 + if-else分支）
        ├── case 0：退出
        └── default：输入错误
```

看到了吗？
- 最外层是**循环**（重复显示菜单）
- 循环里面是**分支**（根据选择做不同操作）
- 每个分支里面是**顺序**（一行一行执行）
- 有些分支里面还有更小的**分支**（if 判断金额是否合法）

**大结构套小结构，层层嵌套** —— 这就是程序的基本组织方式。

## 六、代码的"坏味道"

ATM 程序能跑，功能也都实现了。但是——如果你仔细看，会发现代码有股"坏味道"。

### 6.1 问题1：main 函数太长了

所有代码都堆在 `main` 函数里，有几十行。越往后加功能，代码越长。

想象一下，如果再加10个功能，main 函数会有多长？

### 6.2 问题2：代码重复

存款、取款、转账的逻辑很像：
- 都要检查金额是否大于 0
- 都要检查余额够不够
- 都要打印成功提示和当前余额

这些代码几乎一模一样，都是复制粘贴改了一点点。

### 6.3 问题3：阅读困难

想改"取款"的逻辑？得在一大堆代码里慢慢找。
想加一个新功能？得小心别影响到别的代码。

### 6.4 问题4：没法复用

如果另一个程序也要用"存款"的功能怎么办？只能把代码复制过去。

复制粘贴 = 维护噩梦。改一个地方，所有复制过的地方都要改。

## 💡 思考题

> 完整版（含背景、思考方向、详细解答）见 `思考题.md`。这里给出题目与参考解答要点。

### 题目1：为什么"三种基本结构"就够用了？

只用顺序、分支、循环三种结构，为什么能组合出任意复杂的程序？

> **参考解答**：关键在"少而够用 + 可以嵌套"。三种结构各司其职（顺序=一步步来，分支=按条件选路，循环=重复做），且不可互相替代——循环要停下来常靠分支改变条件（如 `running = 0`）。ATM 的骨架就是「循环套分支，分支里再套顺序」。Böhm 和 Jacopini 在 1966 年证明：任何程序都能只用这三种结构表达。结构很少，但可以嵌套，组合就无限。

### 题目2：case 穿透是 bug 还是特性？

`switch` 里忘了写 `break`，程序会继续执行下面所有 `case`。这是缺陷还是特性？

> **参考解答**：主流观点是「1970 年代遗留的设计，弊大于利」。它能用来让多个 `case` 共用一段代码（`case 1: case 2: 公共代码; break;`），但绝大多数情况是程序员忘记写 `break`，且产生的 bug 极难排查。现代语言（Java、C#、Go）都已禁止隐式穿透。**结论：每个 `case` 后面都要加 `break`**，除非你明确知道自己在用穿透。

### 题目3：循环靠什么结束？死循环是怎么来的？

`while` / `for` 靠什么停下来？漏写 `i++` 会怎样？`while (1)` 一定是 bug 吗？

> **参考解答**：循环唯一的"刹车"是**让条件最终由真变假**。`while` 的刹车在条件里的变量（ATM 靠 `running = 0`），`for` 的刹车在"更新"那一步（漏写 `i++`，条件恒真 → 死循环）。排查方法：盯住"循环条件里的变量"在循环体内有没有被改变。`while (1)` 不一定是 bug——只要循环体里一定有 `break` / `return`，它就是菜单类程序的惯用写法。`for` 与 `while` 可互相改写，`for` 只是"初始化+条件+更新"的语法糖。

### 题目4：结构化程序设计是谁提出来的？

"顺序、分支、循环是程序的三种基本结构"，这句话来自哪里？和后面的函数、模块、架构有什么关系？

> **参考解答**：来自 **Böhm-Jacopini 定理（1966 年）**——任何程序都能只用顺序、分支、循环表达，不需要 `goto`。1968 年 Dijkstra 发表《goto 语句有害论》，指出 `goto` 会让执行路径纠缠不清，推动"结构化程序设计"普及。它与架构一脉相承："不要用 goto"的本质是"**执行路径要清晰可控**"；函数、模块、分层架构，都是在更高层次上做"结构化"。

## 📝 小结

### 一句话总结

**顺序让代码跑起来，分支让代码有选择，循环让代码有力量。三种结构层层嵌套，就能搭出任何程序。**
