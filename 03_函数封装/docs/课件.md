## 一、为什么需要函数？

### 1.1 第2讲的"痛"

回忆一下第2讲的 ATM 程序：
- 所有代码都堆在 `main` 函数里，几十行起步
- 存款、取款、转账的成功提示几乎一模一样，都是复制粘贴
- 想改"取款"的逻辑？得在一大堆代码里慢慢找
- 另一个程序也要用存款功能？只能复制粘贴

这就像一个**没有抽屉的书桌**——所有东西都摊在桌面上，东西越多越乱。

### 1.2 函数就是"抽屉"

**函数**就是给代码找个家，把相关的代码打包在一起，起个名字。

| 没有函数 | 有了函数 |
|:---:|:---:|
| 所有代码堆在main | 每个功能一个函数 |
| 想改功能？慢慢找 | 想改功能？找对应函数 |
| 重复代码？复制粘贴 | 重复代码？抽成函数，到处调用 |
| 代码给别人用？全复制 | 代码给别人用？直接传函数 |

### 1.3 函数封装的本质

**封装 = 打包 + 命名 + 隐藏细节**

想象一个电视遥控器：
- 你只需要按"音量+"键，不用管里面电路怎么工作
- 音量控制的所有细节都"封装"在遥控器内部
- 你只需要知道：按这个键，音量会变大

函数也是一样：
- 调用者只需要知道：传什么参数、得到什么结果
- 函数内部怎么实现的，调用者不用关心
- 内部细节可以随时修改，只要接口不变，调用者就不受影响

这就是**封装的力量**——把复杂藏起来，只暴露简单的接口。

## 二、函数的基本语法

### 2.1 函数的组成

一个函数有四个基本部分：

```c
返回值类型  函数名(参数列表)
{
    函数体（代码）
}
```

对应到我们的代码：

```c
void deposit(void)
{
    double amount = 0.0;
    printf("【存款业务】\n");
    // ... 存款逻辑
}
```

| 部分 | 例子 | 说明 |
|:---:|:---|:---|
| 返回值类型 | `void` | 函数执行完返回什么，void表示不返回 |
| 函数名 | `deposit` | 函数的名字，调用时用它 |
| 参数列表 | `(void)` | 调用时传什么数据，void表示没有参数 |
| 函数体 | `{ ... }` | 函数的具体实现代码 |

### 2.2 函数的三个阶段

**声明 → 定义 → 调用**

#### ① 函数声明（原型）

告诉编译器："有这么一个函数，长这样。"

```c
void deposit(void);  // 分号结尾，没有函数体
```

就像餐厅菜单——告诉你有什么菜、长什么样，但菜的做法不在菜单上。

#### ② 函数定义

函数的具体实现，写清楚函数内部到底做了什么。

```c
void deposit(void)
{
    // 具体代码...
}
```

就像厨房——真正做菜的地方。

#### ③ 函数调用

使用这个函数，让它执行一次。

```c
deposit();  // 调用函数，函数体里的代码会执行一次
```

就像点菜——告诉厨房"我要这个菜"，厨房做好端给你。

### 2.3 为什么要声明？

C语言是"从上往下"编译的。如果函数定义在调用后面，编译器会报错："这是什么函数？我没见过！"

所以有两种写法：

**写法A：定义放在调用前面（不用声明）**
```c
void hello() { printf("Hello!\n"); }

int main()
{
    hello();  // 编译器已经认识 hello 了
    return 0;
}
```

**写法B：先声明，定义放后面（推荐）**
```c
void hello();  // 声明：告诉编译器有这个函数

int main()
{
    hello();  // 编译器：我知道这个函数，继续
    return 0;
}

void hello() { printf("Hello!\n"); }  // 定义在后面
```

为什么推荐写法B？
- 函数多了之后，把所有声明放在一起，一目了然
- 就像书的目录——先看目录就知道整本书有什么
- 多文件编程时，声明写在头文件里（下一讲会学）

## 三、参数传递

### 3.1 为什么需要参数？

如果函数只能做固定的事情，那就太死板了。

```c
// 只能打印100元存款成功
void print_deposit_success()
{
    printf("✅ 存入 100.00 元\n");
}
```

但存款金额是用户输入的，每次不一样啊！

**参数**就是让函数可以接收外部传来的数据，根据数据做不同的事情。

```c
// 打印任意金额的存款成功
void print_success(char* op, double amount)
{
    printf("✅ 操作成功！%s %.2f 元\n", op, amount);
}
```

### 3.2 值传递

C语言的参数传递是**值传递**——把变量的值复制一份传给函数。

```c
void add_one(int x)
{
    x = x + 1;      // 修改的是 x（副本）
    printf("函数内：x = %d\n", x);
}

int main()
{
    int a = 10;
    add_one(a);     // 把 a 的值（10）复制给 x
    printf("函数外：a = %d\n", a);  // a 还是 10！
    return 0;
}
```

输出：
```
函数内：x = 11
函数外：a = 10
```

为什么 `a` 没变？
- 函数里的 `x` 是 `a` 的**副本**，两个不同的变量
- 修改副本，不会影响原来的变量
- 就像你把文件复印一份给别人——别人在复印件上乱写，你的原件不受影响

### 3.3 那我想修改原变量怎么办？

好问题！这就是**指针**的用武之地了——第5讲我们会学。

现在先记住：**参数传递的是值的副本，函数内修改参数不会影响外面的变量。**

## 四、返回值

### 4.1 概念

函数可以执行完之后，**返回一个结果**给调用者。

```c
// 计算两个数的和，返回结果
int add(int a, int b)
{
    return a + b;   // return 后面的值就是返回值
}

int main()
{
    int result = add(3, 5);  // 调用函数，把返回值存到 result 里
    printf("3 + 5 = %d\n", result);  // 输出 8
    return 0;
}
```

### 4.2 return 的作用

`return` 有两个作用：
1. **结束函数**——立即停止执行，从函数里跳出去
2. **返回值**——把值带回给调用者

```c
double get_max(double a, double b)
{
    if (a > b)
    {
        return a;   // a大，返回a，函数结束
    }
    return b;       // 否则返回b
}
```

### 4.3 void 返回值

如果函数不需要返回值，返回值类型写 `void`。

```c
void print_hello()
{
    printf("Hello!\n");
    // 没有 return，函数执行完自动结束
}
```

也可以写 `return;` 来提前结束 void 函数：

```c
void deposit(double amount)
{
    if (amount <= 0)
    {
        printf("金额无效！\n");
        return;   // 提前结束函数，后面的代码不执行了
    }
    // ... 正常存款逻辑
}
```

## 五、函数封装的设计原则

### 5.1 单一职责原则

**一个函数只做一件事，并且把它做好。**

✅ 好的函数名：
- `show_welcome()` —— 显示欢迎界面
- `deposit()` —— 处理存款
- `print_success()` —— 打印成功信息

❌ 不好的函数名：
- `do_everything()` —— 什么都做，肯定做不好
- `deposit_and_withdraw()` —— 两个功能混在一起

为什么单一职责很重要？
- **好理解**：看名字就知道函数做什么
- **好维护**：改存款逻辑，只改 deposit 函数
- **好复用**：需要打印成功信息，调用 print_success 就行

### 5.2 代码复用原则

**同样的代码不要写两遍。**

第2讲里，存款、取款、转账都有类似的成功提示：
```c
// 存款里
printf("✅ 存款成功！存入 %.2f 元\n", amount);
printf("当前余额：%.2f 元\n", balance);

// 取款里
printf("✅ 取款成功！取出 %.2f 元\n", amount);
printf("当前余额：%.2f 元\n", balance);

// 转账里... 又是差不多的
```

第3讲里，抽成一个函数：
```c
void print_success(char* op, double amount)
{
    printf("✅ 操作成功！%s %.2f 元\n", op, amount);
    printf("当前余额：%.2f 元\n", g_balance);
}
```

好处：
- 只写了一遍，不容易出错
- 想改格式，只改一个地方
- 代码更简洁

### 5.3 封装（信息隐藏）原则

**调用者不需要知道函数内部是怎么实现的，只要知道怎么用就行。**

比如你用 `printf`，你需要知道它内部怎么把文字显示到屏幕上吗？
不需要。你只需要知道：传一个字符串，它就会打印出来。

这就是封装的价值——**把复杂藏起来，只暴露简单的接口**。

这个思想会贯穿整个系列：
- 函数封装：把代码细节藏起来
- 模块封装：把文件细节藏起来
- 库封装：把编译细节藏起来
- 框架封装：把整个系统的细节藏起来

## 七、还有问题吗？

函数封装解决了很多问题，但新的问题也来了：

### 问题1：全局变量太危险

`g_balance` 是全局变量，所有函数都能修改它。
- 如果有10个函数都能改余额，改错了都不知道是谁改的
- 全局变量是"公共牧场"——谁都能来踩一脚

**解法预告**：用指针 + 参数传递，让变量的修改更可控（第5讲）。

### 问题2：文件越来越长

函数越来越多，一个文件几百行、上千行...
- 找函数也得翻半天
- 多人协作更麻烦

**解法预告**：多文件编程，把相关的函数放一个文件里（第4讲）。

### 问题3：新增功能要改 switch

现在加一个功能（比如"改密码"），要：
1. 写一个新函数
2. 在 switch 里加一个 case
3. 在菜单里加一行

每加一个功能都要改 main 函数的代码...

**解法预告**：函数指针 + 链表 + 插件机制——新增功能不用改主程序（第12-13讲）。

> 💡 **技术演进的规律**：每解决一个问题，就会遇到新的问题。但每一步，都让代码更好了一点。这就是从程序员到架构师的成长之路。

## 💭 思考题

### 题目1
为什么说"函数是 C 语言中最基础的封装手段"？封装到底是什么意思？

> **参考答案**：封装就是"打包 + 命名 + 隐藏细节"。函数把一段代码打包起来，起个名字，调用者只需要知道怎么调用（传什么参数、返回什么），不需要知道内部怎么实现。这就是最基础的封装。后面的模块、库、框架，都是在更高层次上做同样的事情——把复杂的东西包起来，露出简单的接口。

### 题目2
"值传递"是什么意思？为什么函数里修改参数不会影响外面的变量？

> **参考答案**：值传递的意思是，调用函数时，会把参数的值**复制一份**传给函数。函数里操作的是副本，不是原变量。所以修改副本不会影响外面。这就像你把文件复印一份给同事，同事在复印件上修改，不会影响你的原件。如果想修改原变量，需要传指针（地址），让函数知道原变量在哪——这就是第5讲的内容。

### 题目3
"单一职责原则"说的是什么？违反它会有什么坏处？

> **参考答案**：单一职责原则（SRP）是说一个函数（或模块、类）应该只负责一件事，只有一个改变的理由。违反单一职责的坏处：① 函数又长又乱，不好理解；② 改一个功能可能影响另一个功能，容易引入bug；③ 不好复用——你只想用其中一部分功能，但函数是绑在一起的。

### 题目4
函数声明和函数定义有什么区别？为什么要有声明？

> **参考答案**：函数声明（原型）是告诉编译器"有这么一个函数，长什么样"，没有函数体，以分号结尾。函数定义是函数的完整实现，有函数体。为什么需要声明？因为C语言是从上往下编译的，如果函数定义在调用的后面，编译器还没见到这个函数就会报错。声明就是提前打个招呼："这个函数后面有定义，先别报错。"
