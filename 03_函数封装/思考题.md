## 📖 参考答案

### 题目1：为什么说函数是最基础的封装？

**参考答案**：

"封装"包含两层意思：**打包**和**隐藏**。

**打包**：把相关的代码放在一起，形成一个整体。就像把零散的工具放进一个工具箱——工具箱就是一个"包"。

**隐藏**：把内部的实现细节藏起来，只对外暴露简单的使用方式。就像你用电视遥控器，不需要知道里面的电路，按按钮就行。

函数正好满足这两点：
- 把一段代码打包起来，起个名字（打包）
- 调用者只需要知道传什么参数、返回什么，不需要知道内部怎么实现（隐藏）

生活中的封装：
- 遥控器（封装了电路，暴露了按钮）
- 汽车（封装了发动机，暴露了方向盘和踏板）
- 自动售货机（封装了找零逻辑，暴露了选货按钮）

编程中的封装（从低到高）：
- 函数：封装代码片段
- 模块/文件：封装一组相关函数
- 库：封装编译好的二进制代码
- 框架：封装整个系统的骨架
- 微服务：封装整个业务能力

**所以说，函数是最低层、最基础的封装。后面所有高级的封装，都是在函数的基础上一层一层堆起来的。**

### 题目2：值传递的得与失

**参考答案**：

**值传递的好处**：

1. **安全性**：函数里怎么折腾参数，都不会影响外面的变量。外面的变量是"安全的"。
2. **隔离性**：函数和调用者之间没有副作用，各自独立。
3. **简单**：传值就是复制，逻辑简单，不容易出奇怪的bug。

**值传递的坏处**：

1. **想改原变量不行**：函数里改的是副本，外面看不到。想改？得用指针（多了一层复杂度）。
2. **大对象复制浪费**：如果参数是一个很大的结构体，每次调用都完整复制一份，浪费时间和内存。
3. **只能返回一个值**：函数只能有一个返回值。想返回多个结果？比较麻烦（得用指针参数或者结构体）。

**不同语言的选择**：
- **C语言**：默认值传递，指针可以模拟引用传递——给你选择的自由，但你要自己负责。
- **C++**：值传递 + 引用传递（&）——两种都支持。
- **Java/Python**：基本类型值传递，对象类型引用传递——分情况处理。
- **Fortran**：默认引用传递——历史原因，方便在函数里修改变量。

**设计的权衡**：没有绝对的好坏，是"安全"和"灵活"的权衡。C语言选择了"默认安全，需要灵活的话自己用指针"——这很符合C的哲学：给你底层的控制能力，但你要自己负责。

### 题目3：函数越"小"越好吗？

**参考答案**：

**不是越小越好，也不是越大越好，关键是"职责单一"和"可读性"。**

函数拆得太小的问题：
- **跳转太多，读起来累**：读代码时，一个函数跳转到另一个，再跳转到另一个... 跳来跳去脑子都乱了
- **过度碎片化**：逻辑本来是连贯的，硬拆成几个小函数，反而破坏了整体性
- **命名负担**：每个函数都得起个好名字，拆得太碎起名都费劲

函数写得太长的问题：
- **看不懂**：几百行的函数，读到底都忘了开头在干嘛
- **难维护**：想改一小点，得仔细读完整段代码，生怕改坏了别的
- **难复用**：这么大一坨，别的地方想用也用不上

**判断该不该拆的标准**：

1. **能不能用一句话说清楚这个函数做什么？**
   - 能：可能职责是单一的
   - 不能（"它先做A，再做B，然后如果C的话还做D"）：该拆了

2. **有没有重复的代码？**
   - 类似的代码出现了2次以上：抽成函数

3. **嵌套太深了吗？**
   - if 套 if 套 for 套 if... 三四层以上就该考虑拆了

4. **你需要滚动屏幕才能看完吗？**
   - 一屏看不完的函数，大概率可以拆

**经验法则**：
- 小函数（5-20行）：最理想，一眼看完，职责清晰
- 中等函数（20-50行）：可以接受，逻辑稍复杂但还能hold住
- 大函数（50行以上）：该警惕了，想想能不能拆
- 超大函数（100行以上）：强烈建议重构，几乎肯定可以拆

但记住：**这些都是参考，不是教条。** 最终标准是"读起来舒服不舒服、改起来方便不方便"。

### 题目4：全局变量的争议

**参考答案**：

**为什么大家不喜欢全局变量**：

1. **谁都能改，改乱了找谁？**
   一个全局变量，10个函数都能改。某天值不对了，你得排查10个函数——这就是"公共牧场悲剧"。

2. **隐藏依赖，降低可读性**
   你看一个函数，只看参数以为它只依赖传入的值。结果函数内部偷偷改了全局变量——这就是"隐藏的副作用"。

3. **不好复用**
   带全局变量的函数，搬到另一个程序里很麻烦——你得把全局变量也搬过去，还得确保不跟那边的变量重名。

4. **并发问题**（后续课程会学）
   多个线程同时改全局变量，会出各种奇怪的bug。

**为什么我们还要用**：

1. **方便啊！** 多个函数共享数据，传过来传过去多麻烦，直接全局变量搞定。
2. **有些数据确实是"全局"的**——比如系统配置、程序状态，整个程序就一份。

**不用全局变量的话，怎么共享数据**：

1. **传参（指针）**：把变量的地址传给函数，函数通过指针修改。——第5讲学
2. **结构体打包**：把相关的变量打包成一个结构体，传结构体指针。——第7讲学
3. **静态变量**：限制在一个文件内可见，比全局变量好一点。——第4讲学
4. **封装成"get/set"函数**：不让外部直接改变量，只能通过函数改。——这就是封装思想

**最佳实践**：
- 尽量少用全局变量
- 必须用的话，加前缀（比如 `g_`），让人一眼就知道这是全局的
- 能通过参数传递的，就不要用全局
- 随着我们学习指针、结构体，会发现大部分全局变量都是可以替代的
