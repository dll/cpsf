## 一、什么是指针？

### 1.1 从内存说起

程序运行时，数据存在内存（RAM）里。内存就像一栋超大的酒店：

- 酒店有很多房间，每个房间有**房间号**（地址）
- 每个房间可以住客人（存储数据）
- 找某个人，不需要知道他叫什么，只要知道房间号就行

```
内存酒店
┌──────────────────────────────────┐
│  地址 0x7FFF0000  │  值 = 1000.0  │  ← balance 住在这
├──────────────────────────────────┤
│  地址 0x7FFF0008  │  值 = ???     │  ← 别的变量
├──────────────────────────────────┤
│  地址 0x7FFF0010  │  值 = ???     │
├──────────────────────────────────┤
│  ...                              │
└──────────────────────────────────┘
```

### 1.2 指针就是"房间号"

**指针**是一种特殊的变量，它存的不是普通数据，而是**另一个变量的地址**。

```
普通变量 balance：
  名字：balance
  地址：0x7FFF0000（酒店房间号）
  值：1000.0（房间里住的人）

指针变量 p_balance：
  名字：p_balance
  地址：0x7FFF0020（指针自己也有房间）
  值：0x7FFF0000（存的是 balance 的房间号！）
```

比喻：
- balance 是一个保险箱，里面装着 1000 块钱
- p_balance 是一张纸条，上面写着"保险箱在 0x7FFF0000 号房间"
- 拿着纸条，就能找到保险箱，打开看里面多少钱

### 1.3 为什么要用指针？

回忆第3讲的痛点：ATM 程序用全局变量 `g_balance` 管理余额，所有函数都能随便改。

| 问题 | 全局变量版（第3讲） | 指针版（第5讲） |
|:---|:---|:---|
| 余额在哪 | 全局区，谁都能看见 | main 的局部变量，只有 main 能直接访问 |
| 谁能改 | 所有函数 | 只有 main 授权（传地址）的函数才能改 |
| 出了问题 | 不知道谁改的 | 看谁拿了地址就知道 |
| 函数复用 | 带着全局变量一起搬 | 只传参数，搬到哪都能用 |

**指针的价值：在不使用全局变量的前提下，让函数能修改调用者的变量。**

## 二、指针变量的定义和使用

### 2.1 定义指针变量

```c
int a = 42;         // 普通变量 a，值为 42
int* p = &a;        // 指针变量 p，值为 a 的地址
```

解读 `int* p = &a;`：

| 部分 | 含义 |
|:---:|:---|
| `int*` | 指针类型：指向 int 的指针 |
| `p` | 指针变量名 |
| `&a` | 取变量 a 的地址 |
| `=` | 把 a 的地址赋给 p |

`int*` 的三种写法（完全等价）：
```c
int* p;    // 写法1：* 靠近类型（推荐，强调"int指针"是一个类型）
int *p;    // 写法2：* 靠近变量名
int * p;   // 写法3：两边都空着
```

### 2.2 不同类型的指针

指针的类型决定了"解引用时读几个字节"：

```c
int    a = 42;       // int 占 4 字节
double b = 3.14;     // double 占 8 字节
char   c = 'A';      // char 占 1 字节

int*    pa = &a;     // int* 指针：解引用时读 4 字节
double* pb = &b;     // double* 指针：解引用时读 8 字节
char*   pc = &c;     // char* 指针：解引用时读 1 字节
```

比喻：
- `int*` 像是"读4个房间的钥匙"
- `double*` 像是"读8个房间的钥匙"
- 钥匙类型不对，读出来的数据就是乱的

## 三、两个核心操作：取地址（&）和解引用（*）

### 3.1 取地址运算符 &

`&` 获取变量的内存地址。

```c
int a = 42;
printf("a 的值：    %d\n", a);        // 42
printf("a 的地址：  %p\n", &a);       // 0x7FFF... (类似房间号)
```

比喻：
- 变量 a 是一个人
- `&a` 是问"这个人住在哪个房间" → 得到房间号（地址）

### 3.2 解引用运算符 *

`*` 通过地址访问变量的值。

```c
int a = 42;
int* p = &a;          // p 存着 a 的地址

printf("*p = %d\n", *p);   // 42 —— 通过地址读到了 a 的值

*p = 100;                   // 通过地址修改 a 的值
printf("a = %d\n", a);     // 100 —— a 被改了！
```

比喻：
- p 是一张纸条，写着"房间号 0x7FFF..."
- `*p` 是"按照纸条上的房间号去找，打开门看里面有什么"
- `*p = 100` 是"按照纸条上的房间号去找，把里面的东西换成 100"

### 3.3 & 和 * 是互逆操作

```c
int a = 42;
int* p = &a;      // & 取地址：从变量得到地址

// *p == a        // * 解引用：从地址得到变量
// *&a == a       // 先取地址再解引用，还是原来的变量
// &*p == p       // 先解引用再取地址，还是原来的指针
```

用钥匙比喻记住这两个操作：

| 操作 | 符号 | 比喻 | 作用 |
|:---:|:---:|:---|:---|
| 取地址 | `&` | "你住哪个房间？" | 从变量 → 得到地址 |
| 解引用 | `*` | "按房间号去找人" | 从地址 → 得到变量 |

## 四、指针作为函数参数

### 4.1 值传递的局限

第3讲我们学过：C 语言的函数参数是**值传递**——传的是副本。

```c
void add_one(int x)
{
    x = x + 1;     // 改的是副本
}

int main()
{
    int a = 10;
    add_one(a);
    printf("%d\n", a);   // 还是 10！没变！
    return 0;
}
```

函数里改的是 `a` 的副本，原变量纹丝不动。

### 4.2 指针传递：让函数能修改调用者的变量

```c
void add_one(int* p)     // 参数是指针
{
    *p = *p + 1;         // 通过地址修改原变量
}

int main()
{
    int a = 10;
    add_one(&a);          // 传 a 的地址
    printf("%d\n", a);   // 11！变了！
    return 0;
}
```

**执行过程：**

```
main 函数                          add_one 函数
┌───────────────┐                ┌───────────────────────┐
│ a = 10        │                │                       │
│ &a = 0x7FFF00 │── 传地址 ──→  │ p = 0x7FFF00          │
│               │                │ *p = 10 (读到 a 的值)  │
│               │                │ *p = *p + 1 (改为 11) │
│               │←── 改了 ────  │                       │
│ a = 11  ✓     │                └───────────────────────┘
└───────────────┘
```

### 4.3 值传递 vs 指针传递

| 对比项 | 值传递 | 指针传递 |
|:---|:---|:---|
| 传什么 | 变量的值的副本 | 变量的地址 |
| 函数能改原变量吗 | 不能 | 能 |
| 安全性 | 高（副本随便改） | 需要小心（改的是原件） |
| 比喻 | 给复印件 | 给钥匙 |
| 什么时候用 | 只需要读取数据 | 需要修改原变量 |

### 4.4 ATM 程序的对比

**第3讲（全局变量版）：**
```c
double g_balance = 1000.0;   // 全局变量

void deposit(void)            // 无参数
{
    g_balance += amount;      // 直接改全局变量
}

// 调用
deposit();                    // 看不出用了什么数据
```

**第5讲（指针版）：**
```c
// 余额定义在 main 中（局部变量）
double balance = 1000.0;

void deposit(double* p_balance)  // 参数是指针
{
    *p_balance += amount;         // 通过指针改
}

// 调用
deposit(&balance);               // 明确传了余额的地址
```

指针版的优势：
1. **消灭了全局变量**：余额是 main 的局部变量，不再全局可见
2. **显式依赖**：函数参数列表明确声明"我要操作余额"
3. **控制权在 main**：只有 main 决定把地址传给谁
4. **const 保护**：只读操作用 `const double*`，编译器帮你检查

### 4.5 const 和指针

```c
void query_balance(const double* p);   // 只读：不能通过 p 修改原变量
void deposit(double* p);               // 可写：可以通过 p 修改原变量
```

const 放在 `double*` 前面，表示"指针指向的数据是只读的"。
这是好习惯：只读的指针参数加 const，防止意外修改。

## 五、指针与数组的关系

### 5.1 数组名就是指针

在 C 语言中，数组名本质上是指向数组第一个元素的指针。

```c
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;      // 数组名就是首元素地址

printf("%d\n", *p);        // 10（第一个元素）
printf("%d\n", *(p+1));    // 20（第二个元素）
printf("%d\n", *(p+2));    // 30（第三个元素）
```

### 5.2 指针运算

指针可以加减整数，表示"往前/往后移动几个元素"：

```c
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;

p++;              // p 指向第二个元素（地址加了 sizeof(int)）
printf("%d", *p); // 20

p += 2;           // 再往后移2个
printf("%d", *p); // 40
```

注意：`p+1` 不是地址加 1 个字节，而是加 `sizeof(int)` 个字节（4字节）。
这就是为什么指针有类型——类型决定了每次移动的步长。

### 5.3 数组下标 vs 指针

以下两种写法完全等价：

```c
arr[i]        // 下标写法
*(arr + i)    // 指针写法
```

实际上，C 编译器内部就是用指针方式处理数组的。
`arr[i]` 只是 `*(arr + i)` 的语法糖。

### 5.4 数组名和指针的区别

虽然数组名可以当指针用，但有一个重要区别：

| 特性 | 数组名 | 指针变量 |
|:---|:---|:---|
| 能否重新赋值 | 不能（`arr = ...` 非法） | 能 |
| sizeof | 得到整个数组的大小 | 得到指针本身的大小（8字节/4字节） |
| 本质 | 地址常量 | 变量 |

```c
int arr[5];
int* p = arr;

arr = p;     // 编译错误！数组名是常量，不能赋值
p = arr;     // 正确！指针变量可以赋值

sizeof(arr); // 20（5 * 4字节）
sizeof(p);   // 8（64位系统指针大小）
```

## 六、内存模型简图

程序运行时，内存分为四个区域：

```
┌─────────────────────────────────────────┐
│              代码区（Text）              │  存放程序执行的机器指令
│         只读，程序结束后回收              │  函数的代码在这里
├─────────────────────────────────────────┤
│                                         │
│           全局区（Data/BSS）             │  全局变量、静态变量
│       程序启动时分配，结束时回收          │  第3讲的 g_balance 在这里
│                                         │  第5讲没有全局变量了！
├─────────────────────────────────────────┤
│                                         │
│             栈区（Stack）               │  局部变量、函数参数
│      函数调用时分配，返回时自动回收        │  第5讲的 balance 在这里
│      ↑ 向上生长                         │  指针参数 p_balance 也在这里
│                                         │
├─────────────────────────────────────────┤
│                                         │
│             堆区（Heap）                │  malloc/new 分配的内存
│      手动分配，手动回收（free/delete）    │  不用指针没法操作堆
│      ↓ 向下生长                         │  后续动态内存管理会详细学
│                                         │
└─────────────────────────────────────────┘
```

各区域对比：

| 区域 | 存什么 | 谁管理 | 生命周期 |
|:---|:---|:---|:---|
| 代码区 | 函数的机器指令 | 操作系统 | 程序运行期间 |
| 全局区 | 全局/静态变量 | 操作系统 | 程序运行期间 |
| 栈区 | 局部变量/参数 | 自动 | 函数调用到返回 |
| 堆区 | 动态分配的内存 | 手动 | malloc到free之间 |

为什么指针和内存模型有关？
- 指针可以指向栈上的变量（局部变量的地址）
- 指针可以指向堆上的内存（malloc 返回的地址）
- 指针可以指向全局区的变量
- **但绝不能返回局部变量的地址！**（函数返回后栈上的变量就没了）

## 七、函数指针（预告）

### 7.1 数据指针 vs 函数指针

到现在为止，我们学的指针都是**数据指针**——指向变量的地址。

```c
int a = 42;
int* p = &a;    // 数据指针：指向变量 a
```

但函数也有地址（函数的代码存在代码区，有入口地址）。
**函数指针**就是指向函数地址的指针。

```c
// 声明一个函数指针类型
void (*func_ptr)(double*);    // func_ptr 可以指向 void f(double*) 类型的函数

// 让它指向 deposit 函数
func_ptr = deposit;

// 通过函数指针调用函数（和直接调用一样）
func_ptr(&balance);    // 等价于 deposit(&balance)
```

### 7.2 为什么要学函数指针？

回忆第3讲留下的问题：每加一个 ATM 功能，就要在 switch 里加一个 case。

```c
// 现在的写法：每加功能就改 switch
switch (choice) {
    case 1: query_balance(&balance); break;
    case 2: deposit(&balance); break;
    case 3: withdraw(&balance); break;
    // 加功能就得改这里...
}
```

如果用函数指针，可以把函数"当数据一样"存在数组里：

```c
// 函数指针数组：每个元素是一个函数
void (*operations[])(double*) = {
    NULL,             // 0号位不用
    query_balance,    // 1号位
    deposit,          // 2号位
    withdraw,         // 3号位
    transfer,         // 4号位
};

// 调用：不用 switch 了！
operations[choice](&balance);
```

更进一步：如果把函数指针存到链表里，每个节点就是一个"插件"。
新增功能不需要改主程序，只需要注册一个新插件——这就是**插件框架**的核心思想！

**从数据指针到函数指针，从函数指针到插件框架，这就是从程序员到架构师的演进之路。**

## 八、ATM 指针版对比

### 8.1 全局变量版 vs 指针版

| 对比项 | 第3-4讲（全局变量版） | 第5讲（指针版） |
|:---|:---|:---|
| 余额定义 | `double g_balance` 全局变量 | `double balance` main 局部变量 |
| 函数签名 | `void deposit(void)` | `void deposit(double* p)` |
| 余额修改 | 直接 `g_balance += amount` | 通过指针 `*p += amount` |
| 查询余额 | 直接 `printf(g_balance)` | 通过指针 `printf(*p)` |
| 谁能改余额 | 所有函数 | 只有 main 授权的函数 |
| 函数可复用性 | 差（依赖全局变量） | 好（只依赖参数） |
| 安全性 | 低（谁都能改） | 高（const 保护 + NULL 检查） |

### 8.2 指针版的关键代码

```c
// 余额定义在 main 中
double balance = 1000.0;

// 函数通过指针参数操作余额
void deposit(double* p_balance) {
    if (p_balance == NULL) return;        // NULL 检查
    *p_balance = *p_balance + amount;     // 通过指针修改
}

// 调用时传地址
deposit(&balance);
```

### 8.3 为什么指针更安全？

1. **作用域缩小**：balance 只在 main 中可见，不会意外修改
2. **显式授权**：只有 main 传了地址的函数才能操作余额
3. **const 保护**：只读函数用 `const double*`，编译器保证不写
4. **NULL 检查**：使用前检查指针有效性，防止空指针崩溃
5. **可追溯**：谁拿了地址，就在谁的参数列表里写着

## 九、常见错误和注意事项

### 9.1 野指针

```c
int* p;          // 未初始化的指针（野指针）
*p = 42;         // 危险！p 指向未知地址，可能崩溃

// 正确做法
int* p = NULL;   // 初始化为 NULL
// 使用前检查
if (p != NULL) {
    *p = 42;
}
```

### 9.2 返回局部变量地址

```c
int* get_num()
{
    int num = 42;
    return &num;     // 错误！函数返回后 num 就没了
}

// 正确做法：传参数进来
void get_num(int* p)
{
    *p = 42;         // 通过指针写入调用者的变量
}
```

### 9.3 忘记检查 NULL

```c
void deposit(double* p_balance)
{
    // 没有检查 NULL 就直接用！
    *p_balance += amount;    // 如果 p_balance 是 NULL，程序崩溃！
}

// 正确做法
void deposit(double* p_balance)
{
    if (p_balance == NULL) {     // 先检查
        return;
    }
    *p_balance += amount;        // 再使用
}
```

## 思考题

### 题目1
为什么说指针是 C 语言的灵魂？没有指针会怎样？

> **参考答案**：指针让 C 语言具备了直接操作内存的能力。没有指针，函数无法修改调用者的变量（值传递的局限），无法高效传递大块数据，无法实现动态内存分配，无法构建链表/树等动态数据结构，无法实现回调函数和插件机制。指针是 C 语言连接高级抽象和底层硬件的桥梁，是"程序员直接控制内存"的体现。可以说，没有指针，C 语言就退化成了一个不能操作内存的高级语言，失去了它最核心的价值。但同时指针也是危险的——权力越大责任越大，这就是为什么后续语言（Java、Python）选择隐藏指针，用引用代替。

### 题目2
值传递和指针传递的本质区别是什么？

> **参考答案**：值传递复制的是数据的值，函数操作的是副本；指针传递复制的是地址，函数通过地址找到并操作原变量。本质区别在于"函数看到的是副本还是原件"。值传递像给复印件——别人在复印件上修改不影响原件；指针传递像给钥匙——别人拿着钥匙能打开你的保险箱直接改原件。值传递安全但无法修改原变量；指针传递灵活但需要小心。C 语言的选择是"默认安全（值传递），需要灵活时手动用指针"——把控制权交给程序员，这很符合 C 的哲学。

### 题目3
数组名和指针有什么联系和区别？

> **参考答案**：联系：数组名可以当指针用，`arr[i]` 等价于 `*(arr+i)`，数组名就是首元素的地址。区别：① 数组名是地址常量，不能重新赋值（`arr = p` 非法），指针变量可以随意赋值；② `sizeof(arr)` 得到整个数组的大小，`sizeof(p)` 得到指针本身的大小（8字节）；③ 数组名的地址在编译时就确定了，指针变量的值可以在运行时改变。简而言之，数组名是"不能移动的指针"，指针是"可以移动的数组名"。

### 题目4
空指针（NULL）是什么，为什么要检查 NULL？

> **参考答案**：NULL 是一个特殊的指针值，表示"不指向任何有效地址"（通常是地址 0）。检查 NULL 的原因：① 解引用 NULL 指针会导致段错误（Segmentation Fault），程序崩溃；② NULL 常用来表示"出错了"或"没有数据"（比如 malloc 失败返回 NULL，查找失败返回 NULL）；③ 防御性编程的好习惯——"使用指针前先检查是否为 NULL"就像"开门前先确认钥匙对不对"。不检查 NULL 的后果：轻则程序崩溃，重则安全漏洞（空指针解引用是很多 CVE 漏洞的根源）。
