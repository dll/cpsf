## 一、为什么需要数组？

### 1.1 第5讲的"痛"

第5讲我们用指针解决了全局变量的问题，ATM 变得更安全了。但还有一个痛点没解决：

**只能记住"当前这一笔"交易。**

你存了 500，取了 200，又存了 100——每笔交易做完就忘了。想查看"我今天都干了什么"？对不起，查不到。

而且，ATM 只有一个账户。张三取完钱，李四来取钱——只能用同一个余额。这不合理。

用单变量管理的话：
```c
double balance1 = 1000.0;  // 张三的余额
double balance2 = 2000.0;  // 李四的余额
double balance3 = 500.0;   // 王五的余额
// ... 如果有100个账户呢？
double balance100 = ...;    // 写到崩溃
```

这就像用一张一张的便利贴记账——贴到第 100 张的时候，你的桌子已经被便利贴淹没了。

### 1.2 数组就是"储物柜"

**数组**就是一排编了号的储物柜。

| 单变量 | 数组 |
|:---:|:---:|
| 一张便利贴 | 一排编号的储物柜 |
| `double a, b, c, d, e;` | `double arr[5];` |
| 每个变量单独命名 | 一个名字 + 编号（索引） |
| 想用第100个？再起99个名字 | `arr[99]`，搞定 |

想象银行的一排保险箱：
- 每个保险箱大小一样（同一类型）
- 从 0 开始编号（索引 0, 1, 2, 3...）
- 想找第 3 号？直接 `arr[3]`，一步到位
- 所有保险箱紧挨着排列（连续内存）

**数组就是用"一个名字 + 一个编号"管理一组同类型数据。**

### 1.3 从单变量到数组的思维转变

| 思维方式 | 单变量时代 | 数组时代 |
|:---|:---|:---|
| 存 5 个余额 | `b1, b2, b3, b4, b5` | `balances[5]` |
| 访问第 3 个 | `b3` | `balances[2]`（从0开始） |
| 遍历所有 | 手动写 5 行 | `for (i=0; i<5; i++)` |
| 新增第 6 个 | 定义 `b6` | 改数组大小，代码不变 |
| 传给函数 | 传 5 个参数 | 传数组名（一个参数） |

**核心转变**：从"每个数据一个名字"到"一组数据一个名字 + 编号"。这才是批量思维。

## 二、一维数组的定义与初始化

### 2.1 数组定义

```c
类型 数组名[元素个数];
```

对应到 ATM 代码：

```c
// 定义能存 10 笔交易金额的数组
double trans_amounts[10];

// 定义能管理 5 个账户余额的数组
double account_balances[5];

// 定义能存 5 个账户 ID 的数组
int account_ids[5];
```

**关键点**：
- 元素个数必须是**编译时常量**（整数或 `#define` 常量），不能是变量
- 数组大小在定义时就确定了，之后不能改变（这就是"固定大小"的局限）
- 所有元素的类型必须相同

```c
// ✅ 正确：用 #define 定义的常量
#define MAX_ACCOUNTS 5
double balances[MAX_ACCOUNTS];

// ✅ 正确：直接写数字
double arr[10];

// ❌ 错误：不能用变量（C89标准下）
int n = 10;
double arr[n];   // C99 变长数组，部分编译器支持，但不推荐
```

### 2.2 数组初始化

定义数组时可以同时赋初值：

```c
// 完全初始化：5个值，对应5个元素
double account_balances[5] = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};

// 部分初始化：只给3个值，剩下的自动补0
int arr[5] = {1, 2, 3};       // 等价于 {1, 2, 3, 0, 0}

// 省略大小：编译器自动数
int arr[] = {10, 20, 30};     // 等价于 arr[3]

// 全部初始化为0
int arr[5] = {0};              // 等价于 {0, 0, 0, 0, 0}

// 不初始化：局部数组的值是随机的（垃圾值）
int arr[5];                    // 里面是什么？天知道！
```

ATM 中的实际初始化：

```c
// 多账户数据（初始化好了，开卡即用）
int    account_ids[5]       = {1001, 1002, 1003, 1004, 1005};
double account_balances[5]  = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};

// 交易记录数组（初始为空，运行时填充）
double trans_amounts[10];    // 先不初始化，运行时逐笔存入
```

### 2.3 数组元素的访问

用**索引（下标）**访问数组元素，索引从 **0** 开始：

```c
double account_balances[5] = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};

// 第一个元素：索引 0
account_balances[0]  → 1000.0

// 第三个元素：索引 2
account_balances[2]  → 500.0

// 第五个（最后一个）元素：索引 4
account_balances[4]  → 1500.0

// 修改某个元素
account_balances[2] = 800.0;  // 王五的余额改为 800
```

**为什么从 0 开始？**

数组名是首元素的地址。`arr` = `&arr[0]`。`arr[i]` 实际上是 `*(arr + i)`——从首地址偏移 `i` 个元素。偏移 0 就是第一个，偏移 1 就是第二个。所以索引从 0 开始是**内存地址的自然映射**。

```c
// 假设 arr 的首地址是 0x1000，每个 double 占 8 字节
// arr[0] → *(0x1000 + 0) → 地址 0x1000
// arr[1] → *(0x1000 + 8) → 地址 0x1008
// arr[2] → *(0x1000 + 16) → 地址 0x1010
```

### 2.4 数组越界 —— C语言不会保护你

```c
int arr[5] = {1, 2, 3, 4, 5};

// 访问 arr[5] 或 arr[100] —— 编译不报错！
arr[5]  = 999;   // 写到了数组后面的内存，可能覆盖其他变量
arr[-1] = 888;   // 写到了数组前面的内存，也可能出问题
```

C语言不做越界检查，这是**性能与安全的权衡**。检查越界需要额外指令，C语言选择了"快但不安全"——程序员要自己保证不越界。

这在后面会作为思考题讨论。

## 三、数组遍历 —— for 循环与数组的天作之合

### 3.1 为什么 for 和数组是绝配？

第2讲我们学了 for 循环。当时 for 循环主要用来计数和打印菜单。现在有了数组，for 循环终于找到了真正的用武之地——**遍历数组**。

```c
// 第2讲：for 循环打印5次欢迎语
for (int i = 1; i <= 5; i++) {
    printf("第 %d 次：欢迎光临！\n", i);
}

// 第6讲：for 循环遍历5个账户余额
for (int i = 0; i < 5; i++) {
    printf("账户 %d 余额：%.2f\n", i, account_balances[i]);
}
```

模式完全一样！`i` 从 0 到 4，每次 `+1`，刚好覆盖数组的每个元素。这就是**索引循环**——编程中最常见的循环模式。

### 3.2 遍历的固定套路

```c
// 套路：for (int i = 0; i < 数组大小; i++) { 操作 arr[i]; }

// 遍历打印所有账户
for (int i = 0; i < MAX_ACCOUNTS; i++) {
    printf("ID: %d, 姓名: %s, 余额: %.2f\n",
           account_ids[i], account_names[i], account_balances[i]);
}

// 遍历查找某个账户
int target = 1003;
for (int i = 0; i < MAX_ACCOUNTS; i++) {
    if (account_ids[i] == target) {
        printf("找到了！索引：%d\n", i);
        break;
    }
}

// 遍历计算总余额
double total = 0;
for (int i = 0; i < MAX_ACCOUNTS; i++) {
    total += account_balances[i];
}
printf("所有账户总余额：%.2f\n", total);
```

### 3.3 ATM 中的实际遍历

查看交易记录时遍历交易数组：

```c
// 展示最近10笔交易
int display_count = (trans_count < 10) ? trans_count : 10;
int start = (trans_count <= 10) ? 0 : (trans_count % 10);

for (int i = 0; i < display_count; i++) {
    int idx = (start + i) % 10;  // 循环缓冲区索引
    printf("%d. %s %.2f\n", i+1,
           trans_type_name(trans_types[idx]),
           trans_amounts[idx]);
}
```

这段代码展示了数组的**循环缓冲区**技巧：用取模 `%` 实现索引的循环，超过数组末尾就回到开头，自动覆盖最旧的记录。

## 四、字符数组与字符串

### 4.1 C语言没有 string 类型

很多语言有 `string` 类型：Java 的 `String`，Python 的 `str`，C++ 的 `std::string`。但 **C语言没有**。

在 C 语言中，字符串就是**字符数组**——一排连续的字符，末尾加一个 `'\0'` 标记结束。

```c
// 这就是一个字符串
char name[20] = "张三";

// 实际存储的内容：
// name[0]='张'  name[1]='三'  name[2]='\0'  name[3..19]=未使用
//                                  ↑
//                           字符串结束标志
```

### 4.2 为什么需要 '\0'？

C 语言的字符串函数（printf、strlen、strcpy 等）不知道字符串有多长。它们靠 `'\0'` 判断"字符串到哪结束"。

```c
char name1[20] = "张三";     // 自动在末尾加 '\0'
char name2[]   = "李四";     // 编译器自动算大小（4字节：2个汉字+1个'\0'+对齐）

// 手动逐字符初始化（要自己加 '\0'）
char name3[5] = {'W', 'a', 'n', 'g', '\0'};

// 忘了加 '\0' 的后果：
char name4[4] = {'W', 'a', 'n', 'g'};  // 没有 '\0'！
printf("%s\n", name4);  // 打印完 Wang 后继续往后读，直到遇到 '\0'
                        // 可能输出 "Wang???" 一串乱码
```

### 4.3 字符数组的常见操作

```c
char name[20] = "张三";

// 读取（用 %s，遇到空格/回车停止）
printf("请输入姓名：");
scanf("%s", name);    // 注意：name 前面不加 &（数组名本身就是地址）

// 修改某个字符
name[0] = '李';       // 把"张"改成"李"

// 遍历字符数组
for (int i = 0; name[i] != '\0'; i++) {
    printf("%c\n", name[i]);  // 逐个字符打印
}

// 获取字符串长度（不包括 '\0'）
int len = strlen(name);  // 需要引入 <string.h>
```

### 4.4 ATM 中的字符数组

我们用二维字符数组存储多个账户名：

```c
// 每个账户名最多 20 字节（含 '\0'）
char account_names[5][20] = {"张三", "李四", "王五", "赵六", "钱七"};

// 这是一个"数组的数组"：
// account_names[0] → "张三\0................"
// account_names[1] → "李四\0................"
// account_names[2] → "王五\0................"
// ...

// 访问第3个账户的名字
printf("%s\n", account_names[2]);  // 输出：王五

// 修改第3个账户的名字
strcpy(account_names[2], "王小明");  // 需要引入 <string.h>
```

**二维字符数组**本质上就是"一维数组的数组"——每个元素本身又是一个字符数组。这在后面的二维数组部分会详细讲。

## 五、数组作为函数参数 —— 退化为指针

### 5.1 数组传给函数时发生了什么？

当数组作为参数传给函数时，C 语言不会把整个数组复制过去。它只传**数组首元素的地址**——也就是指针。

这叫做**数组退化为指针**（Array Decay）。

```c
// 以下两种写法完全等价：
void print_array(int arr[10], int n) { ... }   // 看着像传数组
void print_array(int arr[], int n) { ... }     // 看着像传数组
void print_array(int *arr, int n) { ... }      // 实际上传的是指针

// 三种写法在编译器眼里完全一样！arr 就是一个 int 指针
```

### 5.2 为什么退化？

想象一个 1000 个元素的数组，如果传参时完整复制——那就是 4000 字节的内存复制，太浪费了。C 语言选择只传地址（4 或 8 字节），高效。

**代价**：函数内部无法知道数组有多长（因为只拿到了地址，不知道这块内存有多大）。所以需要额外传一个参数告诉函数数组长度。

```c
// 标准做法：数组 + 长度 一起传
void print_balances(double arr[], int n) {
    for (int i = 0; i < n; i++) {
        printf("%.2f ", arr[i]);
    }
}

// 调用
double balances[5] = {1000, 2000, 500, 3000, 1500};
print_balances(balances, 5);   // 传数组名 + 元素个数
```

### 5.3 sizeof 的陷阱

```c
double balances[5] = {1000, 2000, 500, 3000, 1500};

// 在定义数组的地方
printf("%d\n", (int)sizeof(balances));  // 输出 40（5 × 8字节）

// 在函数内部（退化为指针后）
void func(double arr[]) {
    printf("%d\n", (int)sizeof(arr));   // 输出 4 或 8（指针大小！）
    // sizeof(指针) = 4（32位）或 8（64位），不是数组大小
}
```

**所以千万不要在函数里用 `sizeof(arr) / sizeof(arr[0])` 来算数组长度——结果是错的！**

### 5.4 ATM 中的实际用法

ATM 程序中，数组作为全局数据直接在函数中访问。真正的"数组传参"出现在更复杂的场景中，比如查找函数：

```c
// 在数组中查找指定 ID，返回索引
int find_account_by_id(int id)
{
    for (int i = 0; i < MAX_ACCOUNTS; i++) {
        if (account_ids[i] == id) {
            return i;
        }
    }
    return -1;  // 没找到
}
```

如果改成传参版本：

```c
// 传入数组和大小
int find_in_array(int arr[], int n, int target)
{
    for (int i = 0; i < n; i++) {
        if (arr[i] == target) return i;
    }
    return -1;
}

// 调用
int idx = find_in_array(account_ids, MAX_ACCOUNTS, 1003);
```

## 六、数组与指针的关系

### 6.1 数组名就是首元素地址

这是第5讲指针和第6讲数组的交汇点。

```c
int arr[5] = {10, 20, 30, 40, 50};

// 数组名 arr 就是 &arr[0]，即首元素的地址
// 以下两行完全等价：
int *p1 = arr;        // 数组名赋给指针
int *p2 = &arr[0];    // 取首元素地址

// 通过指针访问元素
printf("%d\n", *p1);      // 输出 10（arr[0]）
printf("%d\n", *(p1+1));  // 输出 20（arr[1]）
printf("%d\n", *(p1+2));  // 输出 30（arr[2]）
```

### 6.2 指针运算 —— p+1 到底加了多少？

```c
int    arr_i[5];
double arr_d[5];
char   arr_c[5];

int    *pi = arr_i;
double *pd = arr_d;
char   *pc = arr_c;

// pi+1 加了 sizeof(int) = 4 字节
// pd+1 加了 sizeof(double) = 8 字节
// pc+1 加了 sizeof(char) = 1 字节

// 指针加1，不是加1个字节，而是"前进一步"——步长由类型决定
```

这就是为什么 `arr[i]` 和 `*(arr + i)` 完全等价——编译器内部就是这么实现的。

### 6.3 两种遍历方式

```c
double account_balances[5] = {1000, 2000, 500, 3000, 1500};

// 方式1：数组下标法（直观、易读）
for (int i = 0; i < 5; i++) {
    printf("%.2f\n", account_balances[i]);
}

// 方式2：指针偏移法（灵活、接近底层）
double *p = account_balances;
for (int i = 0; i < 5; i++) {
    printf("%.2f\n", *(p + i));
}

// 方式3：指针递增法（最高效）
for (double *p = account_balances; p < account_balances + 5; p++) {
    printf("%.2f\n", *p);
}
```

ATM 中用指针递增法遍历所有账户：

```c
int    *pid  = account_ids;
double *pbal = account_balances;

for (int i = 0; i < MAX_ACCOUNTS; i++) {
    printf("ID: %d, 余额: %.2f\n", *pid, *pbal);
    pid++;    // 指针前进，指向下一个 int
    pbal++;   // 指针前进，指向下一个 double
}
```

### 6.4 数组名 vs 指针 —— 它们一样吗？

大部分情况下可以混用，但有两个关键区别：

| 区别 | 数组名 | 指针变量 |
|:---:|:---|:---|
| 本质 | 地址常量（不可修改） | 变量（可修改） |
| sizeof | 返回整个数组的大小 | 返回指针本身的大小（4或8） |
| 自增 `++` | ❌ 不行（arr++ 报错） | ✅ 可以（p++ 合法） |
| 赋值 `=` | ❌ 不行（arr = ... 报错） | ✅ 可以（p = ... 合法） |

```c
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;

p++;        // ✅ 指针变量可以自增
// arr++;   // ❌ 数组名是常量，不能自增

p = &arr[2];  // ✅ 指针可以重新赋值
// arr = ...; // ❌ 数组名不能赋值

sizeof(arr);  // 20（整个数组大小）
sizeof(p);    // 4 或 8（指针大小）
```

**记住**：数组名是"不能移动的地址标签"，指针是"可以移动的地址标签"。

## 七、二维数组简介

### 7.1 什么是二维数组？

二维数组就是"数组的数组"——一张表格，有行有列。

```c
// 定义 3行4列 的二维数组
int matrix[3][4] = {
    {1, 2, 3, 4},     // 第0行
    {5, 6, 7, 8},     // 第1行
    {9, 10, 11, 12}   // 第2行
};

// 访问元素：行索引在前，列索引在后
matrix[1][2]  → 7    // 第1行第2列
```

### 7.2 二维字符数组 —— 字符串数组

ATM 中用二维字符数组存储多个账户名：

```c
// 5个账户名，每个最多20字符
char account_names[5][20] = {"张三", "李四", "王五", "赵六", "钱七"};

// account_names 是 5×20 的字符矩阵
// 每一行是一个独立的字符串

// 访问第3个账户名
printf("%s\n", account_names[2]);   // 输出：王五

// 修改第3个账户名的第1个字
account_names[2][0] = '王';         // 修改单个字符
```

### 7.3 二维数组的内存布局

二维数组在内存中仍然是**连续排列**的，按行优先存储：

```
account_names[0][0] ~ account_names[0][19] → 第0行的20个字符
account_names[1][0] ~ account_names[1][19] → 第1行的20个字符
...
```

### 7.4 遍历二维数组

```c
// 双重 for 循环遍历
for (int i = 0; i < 5; i++) {        // 外层遍历行
    for (int j = 0; j < 20; j++) {   // 内层遍历列
        if (account_names[i][j] != '\0') {
            printf("%c", account_names[i][j]);
        }
    }
    printf("\n");
}
```

### 8.2 数据结构设计

```c
/* 多账户用平行数组存储 */
int    account_ids[5]       = {1001, 1002, 1003, 1004, 1005};
char   account_names[5][20] = {"张三", "李四", "王五", "赵六", "钱七"};
double account_balances[5]  = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};

/* 交易记录用循环缓冲区 */
double trans_amounts[10];   /* 交易金额 */
int    trans_types[10];     /* 交易类型 */
int    trans_count = 0;     /* 交易总数 */
```

### 8.3 交易记录的循环缓冲区

这是数组应用的一个经典技巧：

```c
void add_transaction(double amount, int type)
{
    int slot = trans_count % 10;   /* 取模实现循环 */
    trans_amounts[slot] = amount;
    trans_types[slot]   = type;
    trans_count++;
}
```

- 第 1 笔 → 存到 `slot = 0`（1 % 10 = 0）
- 第 2 笔 → 存到 `slot = 1`
- ...
- 第 10 笔 → 存到 `slot = 9`
- 第 11 笔 → 存到 `slot = 0`（11 % 10 = 1...1，覆盖最早的）
- 始终只保留最近 10 笔

## 九、数组的局限

### 9.1 固定大小

数组在定义时大小就确定了，之后不能变。

```c
int arr[10];  // 只能存10个，想存第11个？
// arr[10] = 999;  // 越界！C语言不报错，但这是未定义行为
```

- 想加第 11 个账户？改 `#define MAX_ACCOUNTS 11`，重新编译
- 运行时根据用户需求动态调整大小？数组做不到

### 9.2 平行数组太散

```c
int    ids[5];
char   names[5][20];
double balances[5];
// 改了一个数组的元素，要同步改另外两个
// 一不小心就忘了，数据对不上
```

### 9.3 插入和删除困难

数组是连续内存，中间插入一个元素需要把后面所有元素都后移一位。删除同理。时间复杂度 O(n)。

### 9.4 解法预告

| 局限 | 解决方案 | 哪一讲 |
|:---|:---|:---|
| 平行数组太散 | 结构体打包相关数据 | 第7讲 |
| 固定大小 | 动态内存 malloc/free | 第8讲 |
| 插入删除慢 | 链表（节点指针串联） | 第8讲 |
| 数组 vs 链表 | 对比优劣，选择合适的数据结构 | 第8讲 |

## 💭 思考题

### 题目1
数组名和指针到底有什么区别？它们大部分时候可以互换，但有两个关键不同——你知道吗？

> **参考答案**：① 数组名是地址常量，不能自增、不能赋值；指针是变量，可以移动。② `sizeof(数组名)` 返回整个数组的大小，`sizeof(指针)` 返回指针本身的大小（4或8字节）。编译器看到 `int arr[10]` 时知道它占 40 字节；但传给函数后退化成指针，sizeof 就只剩 4 或 8 了。

### 题目2
为什么 C 语言的数组不做越界检查？访问 `arr[100]`（数组只有 5 个元素）编译器不报错，这是 bug 还是特性？

> **参考答案**：这是"有意的特性"。C 语言的设计哲学是"信任程序员，追求极致性能"。每次访问数组都检查越界，需要额外的比较指令，在 1970 年代的硬件上代价很高。C 选择了不检查——快，但程序员要自己负责。越界访问的后果是"未定义行为"——可能读/写了相邻内存的数据，程序可能崩溃、可能输出乱码、甚至被利用做缓冲区溢出攻击。现代语言（Java、Python）都加了越界检查，但 C 始终没有——这是 C 的哲学。

### 题目3
字符数组末尾为什么要加 `'\0'`？不加会怎样？

> **参考答案**：C 语言没有 string 类型，字符串就是"以 '\0' 结尾的字符数组"。`'\0'` 是字符串结束标志——printf、strlen 等函数靠它判断字符串到哪结束。不加 `'\0'`，这些函数会一直往后读内存，直到偶然遇到一个 0 字节才停——可能读出乱码、可能读到不可访问的内存导致崩溃。`char name[] = "张三"` 这种用字符串字面量初始化的方式会自动加 `'\0'`；但 `char name[4] = {'a','b','c','d'}` 不会，要注意手动补上。

### 题目4
数组的固定大小有什么不便？在实际开发中怎么解决？

> **参考答案**：固定大小意味着：① 必须提前预估最大元素数，估少了越界、估多了浪费内存；② 运行时不能根据需求动态调整大小；③ 想增删中间元素很麻烦（要移动后面所有元素）。解决方案：① 用 `malloc` / `free` 动态分配内存（第8讲），大小可以运行时决定；② 用链表，元素个数不限，增删 O(1)（第8讲）；③ 用结构体数组替代平行数组，把相关数据打包在一起（第7讲）；④ 高级语言用动态数组（C++ vector、Python list），自动扩容。

## 📝 小结

### 一句话总结
**数组是用"一个名字 + 一个索引"管理一组同类型数据的容器——连续内存、随机访问、固定大小。**

### 五个知识点

| # | 知识点 | 关键句 |
|---|--------|--------|
| 1 | 一维数组 | 同类型数据的连续集合，索引从 0 开始 |
| 2 | 数组遍历 | for 循环 + 数组 = 天作之合 |
| 3 | 字符数组 | C 语言没有 string，字符数组 + '\0' 就是字符串 |
| 4 | 数组退化为指针 | 传参时只传地址，丢失长度信息 |
| 5 | 数组与指针 | 数组名 = 首元素地址，但 sizeof 不同、可移动性不同 |

### 预告

数组解决了批量存储的问题，但带来了两个新的痛点：
- 平行数组太散 → **第7讲：结构体**，把相关数据打包到一起
- 固定大小 → **第8讲：链表**，动态大小，随时增删

> 💡 **从单变量到数组，从数组到链表，从链表到框架——每一步都是因为"上一步不够好"，这就是技术演进的动力。**
