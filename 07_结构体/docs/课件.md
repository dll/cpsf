## 一、为什么需要结构体？

### 1.1 第6讲的"痛"：平行数组

第6讲我们用数组管理了 5 个账户和 10 笔交易。但数据是用**平行数组**存储的：

```c
/* 第6讲：三个平行数组分别存储账户的不同属性 */
int    account_ids[5]       = {1001, 1002, 1003, 1004, 1005};
char   account_names[5][20] = {"张三", "李四", "王五", "赵六", "钱七"};
double account_balances[5]  = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};
```

三个数组靠"同一个索引"关联：`ids[i]`、`names[i]`、`balances[i]` 对应同一个账户。

**痛点**：

| 痛点 | 说明 |
|:---|:---|
| 改一处要同步改三处 | 删除第 3 个账户，要同时删 ids[2]、names[2]、balances[2] |
| 看不出数据归属 | `account_ids[3]` 和 `account_balances[3]` 看起来毫无关联 |
| 加字段要加数组 | 想加"开户日期"？再定义 `char dates[5][20]`——第四个数组 |
| 函数参数臃肿 | `void func(int ids[], char names[][20], double bals[], int n)` 四个参数 |
| 排序困难 | 按余额排序，要同步移动三个数组的元素——保证不乱套 |

### 1.2 结构体就是"名片"

**结构体**就是把相关数据打包到一起的自定义类型。

想象一张名片——上面有姓名、电话、邮箱，它们是一个整体。你不会把名片撕成三张纸片分别保管。结构体就是编程世界的"名片"。

| 平行数组 | 结构体 |
|:---:|:---:|
| 三张散落的纸条 | 一张名片 |
| `ids[0]` `names[0]` `balances[0]` | `accounts[0].id` `accounts[0].name` `accounts[0].balance` |
| 三个数组通过索引关联 | 一个结构体内的成员天然绑定 |
| 改一处要同步改三处 | 改一个结构体就行 |
| 加字段要加数组 | 加一个成员就行 |

### 1.3 从平行数组到结构体的思维转变

| 思维方式 | 第6讲（平行数组） | 第7讲（结构体） |
|:---|:---|:---|
| 定义账户 | 三个数组 | 一个结构体类型 |
| 声明变量 | `int ids[5]; char names[5][20]; double bals[5];` | `Account accounts[5];` |
| 访问第i个账户ID | `account_ids[i]` | `accounts[i].id` |
| 访问第i个账户余额 | `account_balances[i]` | `accounts[i].balance` |
| 初始化 | `{1001,...}` `{"张三",...}` `{1000.0,...}` | `{1001, "张三", 1000.0}` |
| 函数参数 | 四个参数（三个数组+长度） | 两个参数（结构体数组+长度） |

**核心转变**：从"相关数据散落在不同数组"到"相关数据打包在一个结构体里"。这就是**数据封装**。

## 二、结构体的定义和使用

### 2.1 定义结构体

```c
/* 定义一个账户结构体 */
struct Account {
    int    id;              /* 账户ID           */
    char   name[20];        /* 账户姓名（字符数组）*/
    double balance;         /* 账户余额          */
};
```

**语法解析**：

- `struct` 是 C 语言关键字，表示"要定义一个结构体类型"
- `Account` 是结构体标签名（tag name），和 `struct` 一起构成类型名
- 花括号内的变量叫**成员**（member），也叫**字段**（field）
- 成员可以是任何类型：基本类型、数组、指针、甚至另一个结构体

**关键点**：
- 结构体定义本身不占内存——它只是"图纸"，告诉编译器"这个类型长什么样"
- 只有声明变量时才分配内存：`struct Account acc1;`
- 成员之间用分号 `;` 分隔，结构体定义末尾也有分号

### 2.2 声明结构体变量

```c
/* 方式1：先定义类型，再声明变量（推荐） */
struct Account {
    int    id;
    char   name[20];
    double balance;
};

struct Account acc1;                    /* 声明一个账户变量 */
struct Account acc2 = {1001, "张三", 1000.0};  /* 声明并初始化 */

/* 方式2：定义类型的同时声明变量 */
struct Account {
    int    id;
    char   name[20];
    double balance;
} acc3, acc4;                          /* acc3 和 acc4 也是变量 */

/* 方式3：不写标签名（匿名结构体），只能用这一次 */
struct {
    int    id;
    char   name[20];
    double balance;
} acc5;                                 /* 只能声明这一个变量 */
```

### 2.3 初始化结构体

```c
/* 完全初始化：按成员顺序赋值 */
struct Account acc1 = {1001, "张三", 1000.0};

/* 部分初始化：只给前面几个，后面自动补0 */
struct Account acc2 = {1002};           /* name="\0", balance=0.0 */

/* 指定初始化（C99）：按成员名初始化，顺序无关 */
struct Account acc3 = {.id = 1003, .name = "王五", .balance = 500.0};

/* 先声明后赋值（逐个成员赋值） */
struct Account acc4;
acc4.id = 1004;
strcpy(acc4.name, "赵六");              /* 字符数组不能用=赋值，要用strcpy */
acc4.balance = 3000.0;
```

### 2.4 结构体数组的初始化

ATM 中的实际使用——结构体数组：

```c
/* 第7讲：一个结构体数组搞定所有账户 */
Account accounts[5] = {
    {1001, "张三", 1000.0},    /* accounts[0] */
    {1002, "李四", 2000.0},    /* accounts[1] */
    {1003, "王五", 500.0},     /* accounts[2] */
    {1004, "赵六", 3000.0},    /* accounts[3] */
    {1005, "钱七", 1500.0}     /* accounts[4] */
};

/* 对比第6讲：三个平行数组 */
int    account_ids[5]       = {1001, 1002, 1003, 1004, 1005};
char   account_names[5][20] = {"张三", "李四", "王五", "赵六", "钱七"};
double account_balances[5]  = {1000.0, 2000.0, 500.0, 3000.0, 1500.0};
```

结构体数组的初始化更清晰——每一行就是一个账户的完整信息，一目了然。

## 三、结构体成员访问：`.` 和 `->` 的区别

### 3.1 点号 `.` 运算符 —— 变量访问成员

当你有一个**结构体变量**（不是指针），用 `.` 访问成员：

```c
Account acc = {1001, "张三", 1000.0};

/* 用 . 访问成员 */
printf("ID: %d\n", acc.id);           /* 输出 1001 */
printf("姓名: %s\n", acc.name);       /* 输出 张三 */
printf("余额: %.2f\n", acc.balance); /* 输出 1000.00 */

/* 修改成员 */
acc.balance += 500.0;                  /* 存款500 */
acc.id = 2001;                         /* 修改ID */
strcpy(acc.name, "张小三");            /* 修改姓名 */
```

**记忆口诀**：**变量用点**（`.`）

### 3.2 箭头 `->` 运算符 —— 指针访问成员

当你有一个**结构体指针**，用 `->` 访问成员：

```c
Account acc = {1001, "张三", 1000.0};
Account *p = &acc;     /* p 是指向 Account 的指针 */

/* 用 -> 访问成员 */
printf("ID: %d\n", p->id);           /* 输出 1001 */
printf("姓名: %s\n", p->name);       /* 输出 张三 */
printf("余额: %.2f\n", p->balance); /* 输出 1000.00 */

/* 修改成员 */
p->balance += 500.0;                  /* 通过指针修改原数据 */
```

**`->` 等价于 `(*p).`**：

```c
/* 以下两种写法完全等价 */
p->id        /* 简洁写法（推荐） */
(*p).id      /* 等价写法（先解引用，再取成员） */

/* 为什么需要 -> ？ */
/* 因为 (*p).id 中的 . 优先级高于 *，必须加括号 */
/* p.id 是错的——p 是指针不是结构体，没有 id 成员 */
```

**记忆口诀**：**指针用箭头**（`->`）

### 3.3 什么时候用 `.` 什么时候用 `->`

| 场景 | 变量类型 | 用什么 | 示例 |
|:---|:---|:---:|:---|
| 结构体变量 | `Account acc` | `.` | `acc.id` |
| 结构体指针 | `Account* p` | `->` | `p->id` |
| 结构体数组元素 | `Account arr[5]` | `.` | `arr[i].id` |
| 结构体数组指针 | `Account* p = arr` | `->` | `p->id` 或 `(p+i)->id` |

```c
Account accounts[5] = { /* ... */ };

/* 用下标访问（变量） → 用点 */
accounts[0].id       /* 第0个账户的ID */
accounts[2].balance  /* 第2个账户的余额 */

/* 用指针访问 → 用箭头 */
Account *p = accounts;
p->id              /* 等价于 accounts[0].id */
(p+2)->balance     /* 等价于 accounts[2].balance */
```

**一句话记住**：**点给变量，箭头给指针**。

## 四、结构体指针（衔接第5讲）

### 4.1 结构体指针的定义

第5讲我们学了指针——"存储变量地址的变量"。结构体指针就是"存储结构体地址的指针"。

```c
Account acc = {1001, "张三", 1000.0};

/* p 是指向 Account 类型的指针 */
Account *p = &acc;

/* 通过指针访问结构体成员 */
p->id        /* 等价于 acc.id */
p->name      /* 等价于 acc.name */
p->balance   /* 等价于 acc.balance */
```

### 4.2 结构体指针遍历结构体数组

这是第5讲指针和第7讲结构体的交汇点：

```c
Account accounts[5] = { /* 5个账户 */ };

/* 方式1：下标法（直观） */
for (int i = 0; i < 5; i++) {
    printf("%d %s %.2f\n",
           accounts[i].id, accounts[i].name, accounts[i].balance);
}

/* 方式2：指针法（衔接第5讲） */
Account *p = accounts;    /* 指针指向数组首元素 */
for (int i = 0; i < 5; i++) {
    printf("%d %s %.2f\n",
           p->id, p->name, p->balance);
    p++;    /* 指针前进，指向下一个结构体 */
}
```

**对比第6讲**——第6讲用三个指针遍历三个平行数组：

```c
/* 第6讲：三个指针同步递增——容易出错 */
int    *pid  = account_ids;
char   (*pname)[20] = account_names;   /* 指向字符数组的指针，语法复杂 */
double *pbal = account_balances;

for (int i = 0; i < 5; i++) {
    printf("%d %s %.2f\n", *pid, *pname, *pbal);
    pid++; pname++; pbal++;   /* 三个指针要同步递增 */
}

/* 第7讲：一个指针搞定 */
Account *p = accounts;
for (int i = 0; i < 5; i++) {
    printf("%d %s %.2f\n", p->id, p->name, p->balance);
    p++;   /* 一个指针递增 */
}
```

### 4.3 指针运算的步长

```c
Account accounts[5];
Account *p = accounts;

/* p+1 加了多少？ */
/* 不是加1个字节，而是加 sizeof(Account) 个字节 */
/* 步长 = sizeof(Account)，编译器自动计算 */

printf("%d\n", (int)sizeof(Account));
/* 可能输出 32（4+20+8）或 40（因内存对齐有填充） */

/* p+1 指向下一个结构体，步长自动适应 */
```

### 4.4 结构体指针作为函数参数

这是结构体指针最重要的应用——让函数能修改原数据：

```c
/* 存款函数：通过指针修改账户余额 */
void deposit(Account* pAcc, double amount) {
    pAcc->balance += amount;    /* 通过指针修改原数据 */
}

/* 调用 */
deposit(&accounts[0], 500.0);  /* 传账户的地址 */
/* accounts[0].balance 变为 1500.0 */
```

## 五、结构体作为函数参数：值传递 vs 指针传递

### 5.1 值传递（复制整个结构体）

```c
/* 值传递：把整个结构体复制一份传进去 */
void print_account_value(Account acc) {
    printf("ID: %d, 姓名: %s, 余额: %.2f\n",
           acc.id, acc.name, acc.balance);
    /* 函数内修改的是副本，不影响原数据 */
    acc.balance = 0.0;
}

/* 调用 */
Account acc = {1001, "张三", 1000.0};
print_account_value(acc);     /* 传整个结构体的副本 */
/* acc.balance 仍然是 1000.0，没有被修改 */
```

**特点**：
- 安全：函数内修改不影响原数据
- 浪费：复制整个结构体（所有成员），结构体大时开销明显
- 适合：只读小结构体，或想保护原数据不被修改

### 5.2 指针传递（只传地址）

```c
/* 指针传递：只传地址（4或8字节），高效 */
void deposit(Account* pAcc, double amount) {
    pAcc->balance += amount;   /* 通过指针直接修改原数据 */
}

/* 只读模式：加 const 保护 */
void print_account_ptr(const Account* p) {
    printf("ID: %d, 姓名: %s, 余额: %.2f\n",
           p->id, p->name, p->balance);
    /* p->balance = 0.0; */   /* 编译报错！const 保护，不可修改 */
}

/* 调用 */
Account acc = {1001, "张三", 1000.0};
deposit(&acc, 500.0);          /* 传地址，函数能修改原数据 */
print_account_ptr(&acc);       /* 传地址，只读不修改 */
```

**特点**：
- 高效：只传地址（4或8字节），不复制数据
- 可修改：通过指针能直接修改原数据
- const 保护：加 `const` 可以防止意外修改（编译器检查）
- 适合：大结构体，或需要修改原数据的场景

### 5.3 两种方式对比

| 对比项 | 值传递 `Account acc` | 指针传递 `Account* p` |
|:---|:---|:---|
| 传的是什么 | 整个结构体的副本 | 结构体的地址（4或8字节） |
| 修改影响原数据 | 不影响 | 影响 |
| 内存开销 | 大（复制所有成员） | 小（只传地址） |
| 安全性 | 天然安全 | 需要 const 保护 |
| 适用场景 | 小结构体、只读 | 大结构体、需修改 |

### 5.4 选择原则

```
函数需要修改原数据吗？
├── 是 → 必须用指针传递
│        void deposit(Account* p, double amt);
│
└── 否（只读）→ 结构体大吗？
    ├── 大（>16字节）→ 用 const 指针
    │   void print(const Account* p);
    │
    └── 小 → 可以值传递
        void print(Account acc);
```

**衔接第5讲**：第5讲我们用指针解决了"函数修改不了全局变量"的问题。现在用结构体指针解决了"函数修改不了结构体"的问题。本质完全一样——传地址让函数操作原数据。

## 六、typedef 类型重定义

### 6.1 为什么需要 typedef

每次使用结构体都要加 `struct` 关键字，很繁琐：

```c
/* 没有 typedef：每次都要写 struct */
struct Account acc1;                /* 声明变量 */
struct Account arr[5];              /* 声明数组 */
void func(struct Account* p);       /* 函数参数 */
```

**typedef** 可以给类型起"短名字"，用起来更简洁：

```c
/* 给 struct Account 起短名 Account */
typedef struct Account Account;

/* 现在不用加 struct 了 */
Account acc1;                       /* 简洁！ */
Account arr[5];                     /* 简洁！ */
void func(Account* p);              /* 简洁！ */
```

### 6.2 typedef 的用法

```c
/* 用法1：先定义结构体，再 typedef 起别名 */
struct Account {
    int    id;
    char   name[20];
    double balance;
};
typedef struct Account Account;     /* 起短名 */

/* 用法2：定义结构体的同时 typedef */
typedef struct {
    int    id;
    char   name[20];
    double balance;
} Account;                          /* 直接起短名 */

/* 用法3：给基本类型起别名（提高可读性） */
typedef double Money;               /* Money 就是 double */
typedef int    AccountId;           /* AccountId 就是 int */

Money price = 99.9;                 /* 等价于 double price = 99.9; */
AccountId id = 1001;                /* 等价于 int id = 1001; */
```

### 6.3 typedef 不是创建新类型

```c
typedef double Money;
Money a = 100.0;
double b = 200.0;
a = b;     /* 完全合法！Money 和 double 是同一个类型 */
b = a;     /* 也合法 */
```

`typedef` 只是给已有类型起**别名**，不创建新类型。就像"张三"也可以叫"老张"——人还是那个人，名字短了。

### 6.4 ATM 中的 typedef

```c
/* 给结构体起短名 */
typedef struct Account Account;
typedef struct Transaction Transaction;

/* 用短名声明变量和函数 */
Account accounts[5];                      /* 简洁 */
void print_account_ptr(const Account* p); /* 简洁 */
void add_transaction(Transaction* trans, const char* type, double amount);
```

## 七、结构体数组

### 7.1 什么是结构体数组

结构体数组就是"元素为结构体的数组"——一盒名片，每张名片都是一个完整的账户信息。

```c
/* 定义结构体数组 */
Account accounts[5] = {
    {1001, "张三", 1000.0},
    {1002, "李四", 2000.0},
    {1003, "王五", 500.0},
    {1004, "赵六", 3000.0},
    {1005, "钱七", 1500.0}
};

/* 访问第 i 个账户的成员 */
accounts[0].id          /* 第0个账户的ID = 1001 */
accounts[2].name        /* 第2个账户的姓名 = "王五" */
accounts[4].balance     /* 第4个账户的余额 = 1500.0 */

/* 遍历结构体数组 */
for (int i = 0; i < 5; i++) {
    printf("ID: %d, 姓名: %s, 余额: %.2f\n",
           accounts[i].id, accounts[i].name, accounts[i].balance);
}
```

### 7.2 结构体数组 vs 平行数组

| 对比项 | 平行数组（第6讲） | 结构体数组（第7讲） |
|:---|:---|:---|
| 定义 | 3 个独立数组 | 1 个结构体数组 |
| 数据归属 | 靠索引关联（隐式） | 天然绑定（显式） |
| 初始化 | 3 组初始化 | 1 组初始化（每行完整） |
| 加字段 | 再加一个数组 | 加一个成员 |
| 删除元素 | 3 个数组同步删 | 删一个结构体 |
| 排序 | 3 个数组同步移动 | 移动结构体即可 |
| 函数参数 | 3 个数组 + 长度 | 1 个数组 + 长度 |

### 7.3 交易记录结构体数组

```c
/* 第7讲：交易记录也是结构体 */
struct Transaction {
    char   type[10];        /* "存款"/"取款"/"转账" */
    double amount;          /* 交易金额 */
    int    target_account;  /* 对方账户ID（转账用） */
};

Transaction transactions[10];  /* 结构体数组 + 循环缓冲区 */

/* 对比第6讲：平行数组 */
double trans_amounts[10];      /* 金额 */
int    trans_types[10];       /* 类型（用整数编码） */
/* 第7讲新增 target_account 字段——平行数组要再加一个数组 */
```

结构体让交易记录的信息更丰富，也更容易扩展。

## 八、数据封装思想

### 8.1 结构体 = 数据打包

结构体的本质是**数据封装**——把相关数据绑在一起，作为一个整体管理。

```
封装前（平行数组）：              封装后（结构体）：
┌──────┐ ┌──────┐ ┌──────┐     ┌─────────────────────┐
│ids[] │ │names[]│ │bals[]│     │ Account             │
│ 1001 │ │"张三" │ │1000  │     │  id = 1001          │
│ 1002 │ │"李四" │ │2000  │ →   │  name = "张三"      │
│ ...  │ │ ...  │ │ ...  │     │  balance = 1000.0   │
└──────┘ └──────┘ └──────┘     └─────────────────────┘
  散落的三张纸条                 一张完整的名片
```

### 8.2 函数 = 行为打包

函数封装的是**行为**——把一段操作逻辑绑在一起，取个名字。

```c
/* 存款函数封装了"存款"的行为 */
void deposit(Account* pAcc, double amount) {
    pAcc->balance += amount;    /* 修改余额 */
    add_transaction("存款", amount, 0);  /* 记录交易 */
}
```

### 8.3 数据 + 行为 = 面向对象的雏形

| 编程范式 | 数据 | 行为 | 关系 |
|:---|:---|:---|:---|
| C 语言（第7讲） | 结构体（数据打包） | 函数（行为打包） | 分离的——函数操作结构体 |
| 面向对象（C++/Java） | 类的属性 | 类的方法 | 绑定的——数据和行在一起 |
| 插件框架（第14讲） | 接口定义数据 | 接口定义行为 | 抽象的——只定义接口不实现 |

```c
/* C 语言的"类" = 结构体 + 操作函数 */

/* 数据（属性） */
struct Account {
    int    id;
    char   name[20];
    double balance;
};

/* 行为（方法） */
void deposit(Account* this, double amount) {    /* this 相当于 self */
    this->balance += amount;
}
void withdraw(Account* this, double amount) {    /* this 相当于 self */
    this->balance -= amount;
}
void query(Account* this) {                      /* this 相当于 self */
    printf("余额: %.2f\n", this->balance);
}
```

这和面向对象语言中的类非常相似——只是 C 语言把数据和函数分开了，面向对象把它们绑在一起。

### 8.4 封装的好处

| 好处 | 说明 |
|:---|:---|
| 内聚性 | 相关数据在一起，修改时不会遗漏 |
| 可读性 | `accounts[i].balance` 比 `account_balances[i]` 更表意 |
| 可扩展性 | 加字段只需加一个结构体成员 |
| 可维护性 | 数据结构变了，只要结构体定义不变，使用代码不用改 |
| 安全性 | 可以通过 const 指针控制读写权限 |

## 九、ATM 结构体实战

### 9.1 设计思路

ATM 结构体版相比第6讲的核心进步：

| 功能 | 第6讲（平行数组） | 第7讲（结构体） |
|:---|:---|:---|
| 账户数据 | 3 个平行数组 | 1 个结构体数组 |
| 交易记录 | 2 个平行数组 | 1 个结构体数组 |
| 交易类型 | 整数编码（1/2/3） | 字符串（"存款"/"取款"/"转账"） |
| 对方账户 | 没有 | 有（target_account 字段） |
| 遍历展示 | 3 个指针同步递增 | 1 个结构体指针递增 |
| 函数参数 | 多个数组 + 长度 | 结构体数组 + 长度 |

### 9.2 数据结构设计

```c
/* 账户结构体 */
struct Account {
    int    id;              /* 账户ID */
    char   name[20];        /* 账户姓名 */
    double balance;         /* 账户余额 */
};

/* 交易记录结构体 */
struct Transaction {
    char   type[10];        /* 交易类型 */
    double amount;          /* 交易金额 */
    int    target_account;  /* 对方账户 */
};

/* typedef 起短名 */
typedef struct Account Account;
typedef struct Transaction Transaction;

/* 结构体数组 */
Account accounts[5] = {
    {1001, "张三", 1000.0},
    {1002, "李四", 2000.0},
    {1003, "王五", 500.0},
    {1004, "赵六", 3000.0},
    {1005, "钱七", 1500.0}
};

Transaction transactions[10];  /* 循环缓冲区 */
```

### 9.3 核心操作对比

**查询余额**：
```c
/* 第6讲：从平行数组取值 */
printf("余额: %.2f\n", account_balances[current_account]);

/* 第7讲：从结构体取成员 */
printf("余额: %.2f\n", accounts[current_account].balance);
```

**存款**：
```c
/* 第6讲：修改平行数组 */
account_balances[current_account] += amount;

/* 第7讲：修改结构体成员 */
accounts[current_account].balance += amount;
```

**遍历所有账户**：
```c
/* 第6讲：三个指针同步递增 */
int    *pid  = account_ids;
double *pbal = account_balances;
for (int i = 0; i < 5; i++) {
    printf("%d %.2f\n", *pid, *pbal);
    pid++; pbal++;
}

/* 第7讲：一个结构体指针 */
Account *p = accounts;
for (int i = 0; i < 5; i++) {
    printf("%d %s %.2f\n", p->id, p->name, p->balance);
    p++;
}
```

**记录交易**：
```c
/* 第6讲：写两个数组 */
trans_amounts[slot] = amount;
trans_types[slot] = type;

/* 第7讲：写一个结构体的成员 */
strcpy(transactions[slot].type, "存款");
transactions[slot].amount = amount;
transactions[slot].target_account = 0;
```

### 9.4 值传递 vs 指针传递演示

```c
/* 值传递：复制整个结构体，函数内修改不影响原数据 */
void print_account_value(Account acc) {
    acc.balance = 0.0;    /* 修改的是副本 */
}
/* 调用后原数据不变 */

/* 指针传递：只传地址，函数内修改影响原数据 */
void print_account_ptr(const Account* p) {
    /* p->balance = 0.0; */  /* 编译报错！const 保护 */
    printf("%d %s %.2f\n", p->id, p->name, p->balance);
}
/* 调用后原数据不变（因为 const 保护） */
```

## 十、结构体的局限与展望

### 10.1 结构体解决了什么

| 第6讲的痛点 | 第7讲的解决 |
|:---|:---|
| 平行数组太散 | 结构体把相关数据打包到一起 |
| 加字段要加数组 | 加一个结构体成员即可 |
| 函数参数臃肿 | 传一个结构体指针即可 |
| 数据归属不清晰 | `accounts[i].balance` 一看就知道属于哪个账户 |

### 10.2 结构体还有什么局限

| 局限 | 说明 | 解决方案 | 哪一讲 |
|:---|:---|:---|:---|
| 大小固定 | 结构体数组大小定死，想动态扩容 | 链表 + malloc/free | 第8讲 |
| 数据和行为分离 | 结构体只有数据，操作逻辑散落在函数中 | 面向对象（类 = 数据+行为） | 第9讲 |
| 浅拷贝问题 | 结构体赋值只复制值，指针成员只复制地址 | 深拷贝函数 | 后续 |
| 内存对齐 | 结构体大小可能大于成员大小之和（有填充字节） | 理解对齐规则 | 本讲思考题 |

### 10.3 演进路线

```
结构体（第7讲）── 数据打包
    ↓ 数据和行为绑在一起
接口抽象（第9讲）── 行为打包
    ↓ 定义接口，隐藏实现
动态加载（第12讲）── 运行时加载
    ↓ 接口 + 动态加载
插件框架（第14讲）── 一切集大成
```

## 思考题

### 题目1
结构体的大小等于各成员大小之和吗？`sizeof(struct {int id; char name[20]; double balance;})` 的结果是什么？

> **参考答案**：不一定相等。结构体大小可能**大于**各成员大小之和，因为**内存对齐**。编译器为了提高 CPU 访问内存的效率（对齐访问更快），会在成员之间插入填充字节（padding）。例如 `int`（4字节）+ `char[20]`（20字节）+ `double`（8字节）= 32 字节，但实际可能因为对齐变成 32 或 40 字节。`int` 后面如果有 `char`，`double` 需要按 8 字节对齐，中间会插入填充。可以用 `#pragma pack(1)` 取消对齐，但会降低访问效率。用 `offsetof` 宏可以查看各成员的偏移量。

### 题目2
结构体赋值（`Account b = a;`）是"浅拷贝"还是"深拷贝"？如果结构体成员是指针，会有什么问题？

> **参考答案**：结构体赋值是**浅拷贝**——逐字节复制所有成员的值。如果成员是基本类型（int、double）或字符数组，浅拷贝没问题。但如果成员是**指针**，浅拷贝只复制指针的值（地址），不复制指针指向的数据。结果两个结构体的指针成员指向同一块内存——一个修改了，另一个也跟着变；一个释放了，另一个就变成了野指针。解决方案是自定义**深拷贝函数**：为指针成员分配新内存，复制指向的数据。本讲的 Account 结构体只有基本类型和字符数组，所以浅拷贝是安全的。

### 题目3
`.` 和 `->` 有什么区别？什么时候该用哪个？`(*p).id` 和 `p->id` 完全等价吗？

> **参考答案**：`.` 用于**结构体变量**访问成员，`->` 用于**结构体指针**访问成员。`(*p).id` 和 `p->id` **完全等价**——`->` 就是 `(*p).` 的语法糖（简写）。使用 `->` 更简洁，推荐使用。注意：`.` 的优先级高于 `*`，所以 `*p.id` 不等于 `(*p).id`——前者是 `*(p.id)`，即先取 p 的 id 成员再解引用，这只有当 p 的 id 成员是指针时才合法。这也是为什么要用括号 `(*p)` 或直接用 `->` 的原因。一句话记住：**变量用点，指针用箭头**。

### 题目4
C 语言的结构体和面向对象语言中的"类"有什么相似之处和不同之处？

> **参考答案**：**相似之处**：结构体把相关数据打包在一起，对应类的"属性"；操作结构体的函数对应类的"方法"。结构体 + 操作函数 = 面向对象编程的雏形。**不同之处**：1) C 结构体只有数据，没有行为——数据和函数是分离的；类把数据和方法绑在一起。2) C 结构体没有访问控制——所有成员都是 public 的；类有 public/private/protected。3) C 结构体没有继承——不能从已有结构体派生新结构体；类支持继承。4) C 结构体没有多态——没有虚函数表；类通过虚函数实现多态。尽管如此，C 程序员可以用"结构体 + 函数指针"模拟面向对象——在结构体里放函数指针成员，就是 C 语言版本的"类"。

> **从平行数组到结构体，从结构体到链表，从链表到框架——每一步都是因为"上一步不够好"，这就是技术演进的动力。**
