## 题目1：结构体的大小等于各成员大小之和吗？

**问题**：你定义了一个结构体：

```c
struct Account {
    int    id;        // 4 字节
    char   name[20];  // 20 字节

};
```

直觉上，`sizeof(struct Account)` 应该是 4 + 20 + 8 = 32 字节。但实际结果可能不是 32——可能是 32，也可能是 40。这是为什么？

**思考方向**：
- 编译器为什么要"多给"结构体分配内存？
- 什么是"内存对齐"？它对性能有什么影响？
- `int`、`double` 各自的对齐要求是什么？
- 能不能用 `#pragma pack` 改变对齐方式？代价是什么？
- `offsetof` 宏能帮你看到什么？

## 题目2：结构体赋值是"浅拷贝"还是"深拷贝"？

**问题**：C 语言支持结构体直接赋值：

```c
Account a = {1001, "张三", 1000.0};
Account b = a;          // 直接赋值，合法吗？
b.balance = 0.0;        // 改 b 的余额
printf("%.2f\n", a.balance);  // a 的余额变了吗？
```

上面这段代码，`a.balance` 不会被修改——因为 Account 的成员都是基本类型和字符数组，赋值时全部复制了。

但如果结构体成员有**指针**呢？

```c
struct Person {
    char* name;        // 指针成员！
    int   age;
};

struct Person p1;
p1.name = (char*)malloc(20);
strcpy(p1.name, "张三");
p1.age = 20;

struct Person p2 = p1;    // 浅拷贝！
// p2.name 和 p1.name 指向同一块内存！
free(p1.name);
printf("%s\n", p2.name);  // p2.name 变成野指针！会发生什么？
```

**思考方向**：
- "浅拷贝"和"深拷贝"的区别是什么？
- 什么情况下浅拷贝是安全的？什么情况下不安全？
- 结构体赋值时，字符数组成员（如 `char name[20]`）是怎么处理的？和指针成员有什么不同？
- 如何为含有指针成员的结构体实现深拷贝？
- C++ 的拷贝构造函数解决了什么问题？C 语言没有它，程序员要怎么做？

## 参考答案

### 题目1：结构体的大小等于各成员大小之和吗？

**参考答案**：

**不一定。结构体大小可能大于各成员大小之和，因为"内存对齐"（Memory Alignment）。**

编译器为了提高 CPU 访问内存的效率，会在结构体成员之间插入"填充字节"（padding）。CPU 读取对齐的数据更快（一次读取），读取未对齐的数据可能需要两次读取甚至触发硬件异常。

**对齐规则**：
- 每个成员的偏移量必须是其自身大小的整数倍
- `int`（4字节）：偏移量必须是 4 的倍数
- `double`（8字节）：偏移量必须是 8 的倍数
- `char`（1字节）：偏移量可以是任意值
- 结构体总大小必须是其最大成员大小的整数倍

**Account 结构体的内存布局**（假设 double 按 8 对齐）：

```
偏移量 0~3:   int id           (4字节)
偏移量 4~23:  char name[20]    (20字节)
偏移量 24~31: double balance   (8字节，偏移量24是8的倍数 ✅)
总大小: 32字节

但如果成员顺序不同:
偏移量 0~3:   int id           (4字节)
偏移量 4~11:  double balance   (需要8对齐，偏移4不是8的倍数 ❌)
              → 填充4字节 (偏移量4~7)
偏移量 8~15:  double balance   (8字节，偏移8是8的倍数 ✅)
偏移量 16~35: char name[20]   (20字节)
总大小: 40字节（需要填充到8的倍数）
```

**验证方法**：
```c
#include <stdio.h>
#include <stddef.h>

int main() {
    printf("sizeof(Account) = %d\n", (int)sizeof(Account));
    printf("offsetof id = %d\n", (int)offsetof(Account, id));
    printf("offsetof name = %d\n", (int)offsetof(Account, name));
    printf("offsetof balance = %d\n", (int)offsetof(Account, balance));
    return 0;
}
```

**如何控制对齐**：
```c
// 取消对齐（结构体大小 = 各成员之和）
#pragma pack(1)
struct PackedAccount {
    int    id;
    char   name[20];
    double balance;
};
// sizeof = 32，但访问 balance 可能变慢
#pragma pack()  // 恢复默认对齐
```

**总结**：内存对齐是"空间换时间"——多占几个字节，换取更快的访问速度。排列成员时，把大的成员放前面可以减少填充（如先放 double 再放 int 再放 char）。

### 题目2：结构体赋值是"浅拷贝"还是"深拷贝"？

**参考答案**：

**结构体赋值是"浅拷贝"（Shallow Copy）。**

浅拷贝就是逐字节复制所有成员的值，不关心成员是什么类型——int 复制值，char 数组复制内容，指针只复制地址。

**安全的情况（本讲的 Account 结构体）**：

```c
struct Account {
    int    id;        // 基本类型：复制值 ✅
    char   name[20];  // 字符数组：复制内容 ✅
    double balance;   // 基本类型：复制值 ✅
};

Account a = {1001, "张三", 1000.0};
Account b = a;    // 浅拷贝——但完全安全，因为所有成员都是值类型
b.balance = 0.0;  // 只改 b，不影响 a
// a.balance 仍然是 1000.0
```

**不安全的情况（成员是指针）**：

```c
struct Person {
    char* name;    // 指针成员
    int   age;
};

struct Person p1;
p1.name = (char*)malloc(20);
strcpy(p1.name, "张三");
p1.age = 20;

struct Person p2 = p1;    // 浅拷贝！
// p2.name = p1.name → 两个指针指向同一块 malloc 的内存！
// 后果：
// 1. 修改 p2.name 的内容 → p1.name 也跟着变（因为是同一块内存）
// 2. free(p1.name) 后 → p2.name 变成野指针（悬空指针）
// 3. 两个指针都 free → double free，程序崩溃
```

**如何实现深拷贝**：

```c
// 深拷贝函数：为指针成员分配新内存
struct Person deep_copy_person(struct Person src) {
    struct Person dst;
    dst.name = (char*)malloc(strlen(src.name) + 1);  // 分配新内存
    strcpy(dst.name, src.name);                       // 复制内容
    dst.age = src.age;
    return dst;
}

// 调用
struct Person p2 = deep_copy_person(p1);
// p2.name 和 p1.name 指向不同的内存，互不影响
```

**字符数组 vs 指针的区别**：

| 对比 | `char name[20]` | `char* name` |
|:---|:---|:---|
| 内存归属 | 数组是结构体的一部分 | 指针指向结构体外的内存 |
| 赋值行为 | 复制内容（安全） | 只复制地址（危险） |
| 浅拷贝安全 | 安全 | 不安全 |

**C++ 的解决方案**：C++ 有拷贝构造函数和 `operator=` 重载，可以自动实现深拷贝。C 语言没有这些机制，程序员必须手写深拷贝函数。这是 C 语言"信任程序员"哲学的又一体现。

### 题目3：`.` 和 `->` 到底有什么区别？

**参考答案**：

**`.` 用于结构体变量，`->` 用于结构体指针。**

```c
Account acc = {1001, "张三", 1000.0};
Account* p = &acc;

// ① acc.id     ✅ 正确：acc 是变量，用 .
// ② acc->id    ❌ 错误：acc 不是指针，不能用 ->
// ③ p.id       ❌ 错误：p 是指针，不是结构体，没有 id 成员
// ④ p->id      ✅ 正确：p 是指针，用 ->
// ⑤ (*p).id    ✅ 正确：先解引用得到结构体，再用 .
// ⑥ *p.id      ❌ 错误！这不是 (*p).id
```

**`(*p).id` 和 `p->id` 完全等价**：

`->` 是 `(*p).` 的语法糖（简写），编译器内部处理方式完全一样。使用 `->` 更简洁、更易读，推荐使用。

**为什么不直接写 `*p.id`**：

因为 `.` 的优先级**高于** `*`。所以 `*p.id` 会被编译器解释为 `*(p.id)`——先取 p 的 id 成员，再解引用。但 p 是指针不是结构体，`p.id` 本身就是语法错误。

**运算符优先级**：

```
优先级从高到低：
  .   （成员访问）
  ->  （指针成员访问）
  *   （解引用）

所以：
  *p.id   →  *(p.id)   → 错误！p 是指针没有 id 成员
  (*p).id →  先解引用，再取 id → 正确！
  p->id   →  等价于 (*p).id → 正确！推荐！
```

**链表场景的体会**：

```c
struct Node {
    int data;
    struct Node* next;
};

struct Node node3 = {30, NULL};
struct Node node2 = {20, &node3};
struct Node node1 = {10, &node2};

// 用 . 访问变量成员
printf("%d\n", node1.data);          // 10
// 用 -> 访问指针指向的结构体成员
printf("%d\n", node1.next->data);    // 20（node1.next 是指针，用 ->）
printf("%d\n", node1.next->next->data);  // 30（链式访问）
```

在链表中，`->` 让代码更简洁——如果写成 `(*(*node1.next).next).data`，可读性极差。`->` 是 C 语言为结构体指针专门设计的语法糖，让"通过指针访问成员"变得自然。

**一句话记住**：**变量用点（.），指针用箭头（->）。**

### 题目4：C 语言的结构体和面向对象的"类"有什么相似和不同？

**参考答案**：

**相似之处**：

| 特性 | C 结构体 | 面向对象的类 |
|:---|:---|:---|
| 数据封装 | 把相关数据打包到一起 | 把属性封装在对象中 |
| 自定义类型 | `typedef struct Account Account` | `class Account { ... }` |
| 实例化 | `Account acc = {1001, "张三", 1000.0};` | `Account acc = new Account(...)` |
| 操作函数 | `void deposit(Account* this, double amt)` | `void Account::deposit(double amt)` |

C 结构体 + 操作函数 = 面向对象编程的**雏形**。

**不同之处**：

| 特性 | C 结构体 | 面向对象的类 |
|:---|:---|:---|
| 数据和行为 | **分离**——结构体只有数据，函数在外面 | **绑定**——数据和方法在一起 |
| 访问控制 | 无——所有成员都是 public | 有 public/private/protected |
| 继承 | 无——不能从已有结构体派生 | 有——子类继承父类 |
| 多态 | 无——没有虚函数表 | 有——虚函数实现运行时多态 |
| 构造/析构 | 无——手动初始化和清理 | 有——自动调用构造/析构函数 |
| this 指针 | 需要手动传——`func(Account* this, ...)` | 隐含——编译器自动传递 this |

**C 语言如何模拟面向对象**：

```c
/* 用结构体 + 函数指针模拟"类" */

struct Account {
    int    id;
    char   name[20];
    double balance;

    /* 函数指针成员 = "方法" */
    void   (*deposit)(struct Account* self, double amount);
    void   (*withdraw)(struct Account* self, double amount);
    double (*query)(struct Account* self);
};

/* "方法"实现 */
void account_deposit(struct Account* self, double amount) {
    self->balance += amount;
}

double account_query(struct Account* self) {
    return self->balance;
}

/* "构造函数" */
void account_init(struct Account* acc, int id, const char* name, double bal) {
    acc->id = id;
    strcpy(acc->name, name);
    acc->balance = bal;
    acc->deposit = account_deposit;   /* 绑定方法 */
    acc->query   = account_query;     /* 绑定方法 */
}

/* 使用 */
int main() {
    struct Account acc;
    account_init(&acc, 1001, "张三", 1000.0);  /* "构造" */

    acc.deposit(&acc, 500.0);    /* "调用方法" */
    printf("%.2f\n", acc.query(&acc));

    return 0;
}
```

**Linux 内核的实例**：

```c
/* Linux 内核的 file_operations——用结构体 + 函数指针模拟"接口" */
struct file_operations {
    int    (*open)(struct inode*, struct file*);
    ssize_t (*read)(struct file*, char __user*, size_t, loff_t*);
    ssize_t (*write)(struct file*, const char __user*, size_t, loff_t*);
    int    (*release)(struct inode*, struct file*);
    /* ... */
};
```

不同的文件系统（ext4、nfs、proc）各自实现这些函数指针，注册到 `file_operations` 结构体中——这就是 C 语言版本的"多态"和"接口"。

**从 C 到 C++**：

C++ 的前身叫"C with Classes"——就是在 C 结构体的基础上加了函数成员、访问控制、继承。理解了 C 结构体 + 函数指针，你就理解了面向对象编程的底层逻辑。从"结构体+函数"到"类"到"接口抽象"到"插件框架"——这就是本课程"从程序员到架构师"的演进路线。
