## 一、为什么需要链表？

### 1.1 第6/7讲的"痛"

第6讲我们用数组管理交易记录，第7讲用结构体改进了数据组织。但有一个痛点始终没解决：

**数组的大小是固定的。**

```c
/* 第6讲：固定数组 */
double trans_amounts[10];    /* 最多10笔交易，超过就覆盖最旧的 */
Account accounts[5];          /* 最多5个账户，想加第6个？改代码重新编译 */
```

想象一家银行开业，一开始只有5个客户，用 `accounts[5]` 够了。但银行越做越大，客户从5个涨到50个、500个、5000个——每次都要改数组大小、重新编译、重新部署？这太不合理了。

再想想交易记录：`trans[10]` 只能存10笔，第11笔就覆盖第1笔。客户想查一年前的交易记录？对不起，早被覆盖了。

### 1.2 链表就是"动态火车"

**链表**就是一列可以随时加车厢、摘车厢的火车。

| 固定数组 | 链表 |
|:---:|:---:|
| 一排固定的储物柜 | 一列可以伸缩的火车 |
| `double arr[10];` | `Node* head;` |
| 编译时就定好大小 | 运行时动态增长/缩短 |
| 想加第11个？改代码 | 想加多少加多少，malloc 分配 |
| 内存连续，随机访问快 | 内存不连续，但大小灵活 |
| 超出上限就溢出/覆盖 | 没有上限（直到内存耗尽） |

想象一列火车：
- 每节车厢装着货物（数据域：金额、类型等）
- 车厢之间有挂钩连接（指针域：next 指针）
- 想加车厢？在车尾挂一节新的就行
- 想摘车厢？解开挂钩，运走就行
- 不需要一开始就知道要多少节车厢

**链表就是用"指针串联的节点"管理一组数据，大小随时变化。**

## 二、单链表的结构

### 2.1 节点 = 数据域 + 指针域

链表的基本单位是**节点（Node）**。每个节点包含两部分：

```
┌──────────────────────────┐
│        数据域         │  ← 存储实际数据（金额、类型、名称等）
├──────────────────────────┤
│   指针域 (next)      │  ← 存储下一个节点的地址
└──────────────────────────┘
```

用 C 语言定义一个交易记录节点：

```c
typedef struct TransactionNode {
    /* ---- 数据域 ---- */
    double amount;                  /* 交易金额 */
    int    type;                    /* 交易类型 */
    char   desc[40];                /* 交易描述 */

    /* ---- 指针域 ---- */
    struct TransactionNode* next;   /* 指向下一个节点 */
} TransactionNode;
```

**注意**：`next` 的类型是 `struct TransactionNode*`，即指向"自己这个结构体"的指针。这种"自引用结构"是链表的标志性特征。

### 2.2 火车车厢比喻

```
head ──> [车厢A] ──> [车厢B] ──> [车厢C] ──> NULL
          |next=A    |next=B    |next=NULL
          数据        数据        数据
```

- **head**：火车头（头指针），指向第一节车厢
- **每个节点**：一节车厢，里面装着货物，后面挂钩连着下一节
- **next = NULL**：最后一节车厢，后面没有车厢了
- **head = NULL**：一节车厢都没有（空链表）

### 2.3 链表 vs 数组的内存布局

```
数组（连续内存）：
┌────┬────┬────┬────┬────┐
│ 0  │ 1  │ 2  │ 3  │ 4  │   ← 编号访问：arr[2]，O(1)
└────┴────┴────┴────┴────┘
 地址: 100  104  108  112  116    ← 连续排列

链表（分散内存，靠指针串联）：
head ──> [data|next=200]     地址: 100
              ↓
          [data|next=350]    地址: 200
              ↓
          [data|next=NULL]   地址: 350     ← 必须遍历：O(n)
```

**数组**像一排紧挨着的储物柜，编号直接定位。
**链表**像散落在各地的仓库，只能顺着一根线索（指针）逐个找。

## 三、链表创建与销毁

### 3.1 创建节点：malloc

链表节点在**堆（Heap）**上分配，用 `malloc` 函数：

```c
TransactionNode* create_trans_node(double amount, int type, const char* desc)
{
    /* 1. malloc 分配内存 */
    TransactionNode* node = (TransactionNode*)malloc(sizeof(TransactionNode));

    /* 2. 检查是否分配成功 */
    if (node == NULL) {
        printf("错误：内存分配失败！\n");
        return NULL;
    }

    /* 3. 填充数据域 */
    node->amount = amount;
    node->type = type;
    strncpy(node->desc, desc, 39);
    node->desc[39] = '\0';

    /* 4. 指针域设为 NULL */
    node->next = NULL;

    return node;
}
```

**对比第6讲**：第6讲的数组在编译时就分配好内存（栈上或静态区），不需要 malloc。链表每个节点都是运行时动态分配的。

**内存模型回顾**（第5讲）：
- 栈（Stack）：局部变量，自动分配释放，大小有限
- 堆（Heap）：malloc 分配，手动管理，空间大但需小心
- 链表节点存在堆上——所以能动态增长！

### 3.2 销毁链表：free

malloc 分配的内存**不会自动释放**。如果不手动 free，就会造成**内存泄漏（Memory Leak）**。

```c
void trans_destroy(void)
{
    TransactionNode* cur = trans_head;

    while (cur != NULL) {
        TransactionNode* tmp = cur;   /* 保存当前节点 */
        cur = cur->next;              /* 先移到下一个 */
        free(tmp);                    /* 再释放当前的 */
    }

    trans_head = NULL;  /* 头指针置空 */
}
```

**关键易错点**：不能先 free 再访问 next！

```c
/* 错误写法：free 后访问 cur->next 是未定义行为 */
free(cur);
cur = cur->next;   // 错！cur 已经被释放

/* 正确写法：先保存 next，再 free */
TransactionNode* tmp = cur;
cur = cur->next;
free(tmp);
```

这就像拆除火车车厢：要先记住下一节车厢的位置，再拆当前这节。如果先拆了，就找不到下一节了。

### 3.3 内存泄漏的危害

```c
/* 反面教材：只 malloc 不 free */
void bad_function(void)
{
    TransactionNode* node = malloc(sizeof(TransactionNode));
    node->amount = 100;
    /* 函数结束，node 变量消失，但内存没释放！ */
    /* 这块内存永远没法回收了——内存泄漏！ */
}
```

内存泄漏就像你借了一堆火车车厢，用完不还——停车场（内存）越来越满，最终系统崩溃。

**好习惯**：每个 malloc 都要有对应的 free。

## 四、增：头部插入与尾部插入

### 4.1 头部插入

在链表头部插入新节点——新的数据排最前面。

```
插入前：  head -> A -> B -> C -> NULL
插入后：  head -> NEW -> A -> B -> C -> NULL
```

步骤：
1. 创建新节点
2. 新节点的 next 指向原来的头节点
3. 头指针指向新节点

```c
void trans_insert_head(double amount, int type, const char* desc)
{
    TransactionNode* node = create_trans_node(amount, type, desc);
    if (node == NULL) return;

    node->next = trans_head;   /* 新节点指向旧头 */
    trans_head = node;          /* 头指针指向新节点 */
}
```

**时间复杂度**：O(1) —— 只改两个指针，不需要遍历。

**对比数组**：数组头部插入需要把所有元素后移，O(n)。

### 4.2 尾部插入

在链表尾部追加新节点——新的数据排最后面。

```
插入前：  head -> A -> B -> C -> NULL
插入后：  head -> A -> B -> C -> NEW -> NULL
```

步骤：
1. 创建新节点
2. 如果链表为空（head == NULL），直接让 head 指向新节点
3. 否则，遍历到最后一个节点，让它指向新节点

```c
void trans_insert_tail(double amount, int type, const char* desc)
{
    TransactionNode* node = create_trans_node(amount, type, desc);
    if (node == NULL) return;

    /* 情况1：链表为空 */
    if (trans_head == NULL) {
        trans_head = node;
        return;
    }

    /* 情况2：遍历到最后一个节点 */
    TransactionNode* cur = trans_head;
    while (cur->next != NULL) {
        cur = cur->next;
    }
    cur->next = node;
}
```

**时间复杂度**：O(n) —— 需要遍历到链表末尾。

**优化方案**：维护一个尾指针 `tail`，尾部插入可达 O(1)。但增加尾指针后，头部插入和删除操作需要额外维护 tail，增加了复杂度。

**ATM中的应用**：交易记录用尾部插入，保证时间顺序（先发生的在前）。

## 五、删：按值删除与按位置删除

### 5.1 按值删除

删除链表中第一个金额匹配的交易记录。

```
删除前：  head -> A -> B -> C -> NULL  （删B）
删除后：  head -> A -> C -> NULL
                        B 被 free 回收
```

步骤：
1. 链表为空，直接返回
2. 要删的是头节点：头指针后移，free 旧头节点
3. 要删的是中间/末尾节点：找到**前驱节点**，修改指针跳过被删节点
4. free 被删节点

```c
void trans_delete_by_amount(double amount)
{
    if (trans_head == NULL) return;

    /* 情况1：删头节点 */
    if (trans_head->amount == amount) {
        TransactionNode* tmp = trans_head;
        trans_head = trans_head->next;
        free(tmp);
        return;
    }

    /* 情况2：删中间/末尾 */
    TransactionNode* prev = trans_head;
    TransactionNode* cur  = trans_head->next;

    while (cur != NULL) {
        if (cur->amount == amount) {
            prev->next = cur->next;  /* 前驱跳过当前 */
            free(cur);
            return;
        }
        prev = cur;
        cur = cur->next;
    }
}
```

**关键**：删除链表节点需要保存"前驱节点"的指针。因为要修改前驱的 next 指针，让它跳过被删节点。

**比喻**：从火车中摘掉一节车厢——要先把前后两节车厢重新挂钩，然后运走被摘的车厢。

### 5.2 按位置删除

按位置删除的逻辑类似，只是判断条件从"值匹配"变成"位置匹配"。

```c
void delete_at_position(int pos)
{
    if (trans_head == NULL || pos < 0) return;

    /* 删第0个（头节点） */
    if (pos == 0) {
        TransactionNode* tmp = trans_head;
        trans_head = trans_head->next;
        free(tmp);
        return;
    }

    /* 找到第 pos-1 个节点（前驱） */
    TransactionNode* prev = trans_head;
    for (int i = 0; i < pos - 1 && prev->next != NULL; i++) {
        prev = prev->next;
    }

    if (prev->next == NULL) return;  /* 位置超出范围 */

    TransactionNode* target = prev->next;
    prev->next = target->next;
    free(target);
}
```

## 六、改：修改节点数据

修改链表节点数据，需要先找到目标节点，然后直接修改其数据域。

```c
/* 修改指定金额的交易记录类型 */
void trans_modify_type(double amount, int new_type)
{
    TransactionNode* cur = trans_head;

    while (cur != NULL) {
        if (cur->amount == amount) {
            cur->type = new_type;  /* 直接修改数据域 */
            return;
        }
        cur = cur->next;
    }
}
```

**关键**：通过指针找到节点后，直接用 `cur->field = new_value` 修改。修改本身是 O(1)，但查找是 O(n)。

**对比数组**：数组修改 `arr[i] = new_value` 是 O(1)（直接索引）。链表修改需要先遍历查找，整体是 O(n)。

## 七、查：查找与遍历

### 7.1 遍历

遍历链表就是从头到尾逐个访问每个节点。

```c
void trans_traverse(void)
{
    int index = 1;
    TransactionNode* cur = trans_head;

    while (cur != NULL) {
        printf("%d: %.2f %s\n", index, cur->amount, cur->desc);
        cur = cur->next;   /* 移动到下一个节点 */
        index++;
    }
}
```

**对比第6讲**：
```c
/* 第6讲：数组遍历 */
for (int i = 0; i < 10; i++)
    printf("%f", trans[i]);

/* 第8讲：链表遍历 */
for (cur = head; cur != NULL; cur = cur->next)
    printf("%f", cur->amount);
```

数组用索引 `i`，从 0 到 N-1。链表用指针 `cur`，从头到 NULL。

### 7.2 查找

查找就是遍历的过程中比较数据：

```c
AccountNode* acct_find_by_id(int id)
{
    AccountNode* cur = acct_head;

    while (cur != NULL) {
        if (cur->id == id) {
            return cur;  /* 找到了，返回节点指针 */
        }
        cur = cur->next;
    }

    return NULL;  /* 没找到 */
}
```

**时间复杂度**：O(n) —— 最坏情况要遍历整个链表。

**对比数组**：数组查找也是 O(n)（线性查找），但数组可以用二分查找（如果有序）达到 O(log n)，链表做不到二分查找（因为不能随机访问）。

## 八、链表 vs 数组对比

| 特性 | 数组 | 链表 |
|:---:|:---|:---|
| **大小** | 固定，编译时确定 | 动态，运行时随时变化 |
| **内存** | 连续分配 | 分散分配，靠指针串联 |
| **访问** | 随机访问 `arr[i]`，O(1) | 顺序访问，必须从头遍历，O(n) |
| **头部插入** | 需要所有元素后移，O(n) | 只改两个指针，O(1) |
| **尾部插入** | 已知大小则 O(1) | 需遍历到末尾 O(n)，有尾指针则 O(1) |
| **删除** | 需要元素前移，O(n) | 修改指针即可，找到后删除 O(1) |
| **内存开销** | 无额外开销 | 每个节点多一个 next 指针（4或8字节） |
| **缓存** | 连续内存，缓存友好 | 分散内存，缓存不友好 |
| **内存管理** | 自动（栈）或手动（malloc 数组） | 手动 malloc/free |
| **越界** | 有越界风险 | 无越界问题（但有空指针风险） |
| **适用场景** | 大小已知、频繁随机访问 | 大小未知、频繁增删 |

**选择原则**：
- 需要随机访问、大小已知 → 用数组
- 需要频繁增删、大小动态变化 → 用链表

## 九、链表在插件框架中的应用

### 9.1 插件链表管理（预告第12讲）

在插件框架中，每加载一个插件就创建一个链表节点，挂到插件链表上。框架通过遍历链表来调用每个插件的功能。

```c
/* 简化版插件节点（第12讲会扩展） */
typedef struct PluginNode {
    char name[20];              /* 插件名称 */
    char feature[40];           /* 插件功能描述 */
    struct PluginNode* next;    /* 指向下一个插件 */
} PluginNode;

/* 加载插件 = 头部插入到插件链表 */
void load_plugin(PluginNode** head, const char* name, const char* feature)
{
    PluginNode* p = malloc(sizeof(PluginNode));
    strcpy(p->name, name);
    strcpy(p->feature, feature);
    p->next = *head;   /* 头部插入 */
    *head = p;
}

/* 调用所有插件 = 遍历链表 */
void run_all_plugins(PluginNode* head)
{
    PluginNode* cur = head;
    while (cur != NULL) {
        printf("执行插件：%s（%s）\n", cur->name, cur->feature);
        cur = cur->next;
    }
}
```

ATM 系统加载插件的过程：
```
load_plugin: 汇率查询   →  head -> [汇率查询] -> NULL
load_plugin: 积分兑换   →  head -> [积分兑换] -> [汇率查询] -> NULL
load_plugin: 电子发票   →  head -> [电子发票] -> [积分兑换] -> [汇率查询] -> NULL

run_all_plugins: 遍历链表，依次执行每个插件
```

第12讲将把插件结构体扩展为包含**函数指针**的接口，实现真正的多态调用。

### 9.2 配置化菜单（预告第13讲）

当前 ATM 的菜单是写死的：

```c
void show_menu(void)
{
    printf("  1. 查询余额\n");
    printf("  2. 存款\n");
    printf("  3. 取款\n");
    // ... 固定菜单
}
```

第13讲会用链表实现"配置化菜单"——每个菜单项是一个链表节点，可以动态增删：

```c
/* 菜单项节点 */
typedef struct MenuItem {
    int id;                      /* 菜单编号 */
    char label[40];              /* 菜单文本 */
    void (*handler)(void);       /* 处理函数（函数指针） */
    struct MenuItem* next;        /* 指向下一个菜单项 */
} MenuItem;

/* 动态添加菜单项 */
void add_menu_item(MenuItem** head, int id, const char* label, void (*handler)(void))
{
    MenuItem* item = malloc(sizeof(MenuItem));
    item->id = id;
    strcpy(item->label, label);
    item->handler = handler;
    item->next = *head;
    *head = item;
}

/* 遍历链表显示菜单（不是写死的 printf！） */
void show_dynamic_menu(MenuItem* head)
{
    MenuItem* cur = head;
    while (cur != NULL) {
        printf("  %d. %s\n", cur->id, cur->label);
        cur = cur->next;
    }
}
```

这样，加载一个插件就自动多一个菜单项，卸载插件就自动少一个菜单项——完全动态，不用改代码！这就是链表在架构设计中的威力。
