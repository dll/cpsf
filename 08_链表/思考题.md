## 题目1：链表为什么不能像数组那样随机访问？

**问题**：数组可以用 `arr[5]` 一步定位到第6个元素，时间复杂度是 O(1)。但链表不能直接用 `list[5]` 访问第6个节点，必须从头开始逐个遍历。这是为什么？

如果要实现一个函数 `get_at(Node* head, int index)` 返回链表第 index 个节点的数据，时间复杂度是多少？

```c
/* 想要实现这个函数 */
double get_at(TransactionNode* head, int index)
{
    // 怎么写？
}
```

**思考方向**：
- 数组在内存中是怎样排列的？链表呢？
- 为什么数组的 `arr[i]` 能一步到位？（地址计算公式是什么？）
- 链表的节点分散在内存各处，要找第5个节点，除了从头遍历还有别的办法吗？
- 这对链表的适用场景有什么影响？

---

### 参考答案

**根本原因**：内存布局不同。

数组在内存中是**连续排列**的，所以可以用地址公式直接计算任意元素的位置：

```
arr[i] 的地址 = base_address + i * sizeof(元素)
```

编译器看到 `arr[5]`，会自动算出 `arr + 5 * sizeof(double)`，一步到位。

链表的节点是 **malloc 分散分配**的，每个节点的位置不确定，只能靠 `next` 指针一个一个找。没有公式能直接算出第5个节点在哪里。

```c
double get_at(TransactionNode* head, int index)
{
    TransactionNode* cur = head;
    for (int i = 0; i < index && cur != NULL; i++) {
        cur = cur->next;
    }
    if (cur == NULL) {
        printf("索引越界\n");
        return -1.0;
    }
    return cur->amount;
}
```

**时间复杂度**：O(n) —— 最坏情况要遍历 n 个节点。

这就是为什么：
- 需要频繁随机访问（如二分查找）→ 用数组
- 需要频繁增删、大小动态变化 → 用链表

## 题目2：malloc 分配的内存忘记 free 会怎样？

**问题**：下面的代码有什么问题？如果这种代码在长期运行的程序中反复执行，会发生什么？

```c
void process_transaction(void)
{
    TransactionNode* node = malloc(sizeof(TransactionNode));
    node->amount = 500.0;
    node->type = 1;
    node->next = NULL;
    /* 函数结束了，node 变量消失 */
    /* 但 malloc 分配的内存没有被 free！ */
}
```

**思考方向**：
- `node` 是局部变量，在栈上。函数结束后 `node` 变量会怎样？
- `malloc` 分配的内存在哪里（栈还是堆）？谁来回收？
- 如果这个函数被调用 100 万次，每次泄漏一个节点，会发生什么？
- 程序结束后，操作系统会回收泄漏的内存吗？那为什么还要 free？

---

### 参考答案

**问题**：这段代码会造成**内存泄漏（Memory Leak）**。

`node` 是局部变量，存在栈上，函数结束后自动销毁。但 `malloc` 分配的内存存在**堆**上，不会自动回收。虽然 `node` 指针消失了，但堆上的那块内存还占着，而且再也找不到它的地址了——没法 free 了。

**长期运行的危害**：
- 每次调用泄漏一个节点（约 48 字节）
- 调用 100 万次 → 泄漏约 48 MB
- 调用 1 亿次 → 泄漏约 4.8 GB，系统内存耗尽
- 最终导致程序崩溃或系统变慢

**程序结束后**：现代操作系统会在进程结束时回收该进程的所有内存（包括泄漏的）。所以短生命周期的程序泄漏不致命。但在以下场景中，内存泄漏是致命的：
- 7x24 小时运行的服务器程序（Web服务器、数据库、操作系统内核）
- 嵌入式系统（路由器、物联网设备，内存很小且不重启）

**好习惯**：每个 malloc 都要有对应的 free。可以遵循"谁分配谁释放"原则。

## 题目3：有序链表的插入怎么做？

**问题**：假设交易记录链表按金额**从小到大**排序。现在要插入一笔新交易，插入后链表仍保持有序。该怎么写？时间复杂度是多少？

```c
/* 按金额从小到大有序插入 */
void trans_insert_sorted(double amount, int type, const char* desc)
{
    /* 怎么写？ */
}
```

**思考方向**：
- 需要找到第一个金额大于新节点的位置，插在它前面
- 如果所有节点金额都比新节点小，插在哪里？
- 如果链表为空呢？
- 和"尾部插入"有什么区别？

---

### 参考答案

有序插入需要在遍历过程中找到"第一个比新节点大的位置"，插在它前面。

```c
void trans_insert_sorted(double amount, int type, const char* desc)
{
    TransactionNode* node = create_trans_node(amount, type, desc);
    if (node == NULL) return;

    /* 情况1：链表为空 或 新节点应排在最前面 */
    if (trans_head == NULL || trans_head->amount >= amount) {
        node->next = trans_head;
        trans_head = node;
        return;
    }

    /* 情况2：找到第一个比 amount 大的节点，插在它前面 */
    TransactionNode* cur = trans_head;
    while (cur->next != NULL && cur->next->amount < amount) {
        cur = cur->next;
    }
    /* 现在 cur->next 要么是 NULL（到了末尾），要么是第一个 >= amount 的节点 */
    node->next = cur->next;
    cur->next = node;
}
```

**时间复杂度**：O(n) —— 最坏情况需要遍历到链表末尾。

**与尾部插入的区别**：
- 尾部插入：总是加到最后，不关心顺序
- 有序插入：找到正确位置插入，保持有序

**应用场景**：优先队列（按优先级排序的链表）、按时间排序的交易记录等。

## 题目4：链表有环会怎样？如何检测？

**问题**：如果链表的某个节点的 `next` 指针不是指向后面的节点，而是指向前面的某个节点（甚至自己），就形成了"环"（Circular Linked List）。

```c
/* 制造一个环 */
head -> A -> B -> C -> D -> NULL
                   ↑___________|
/* 如果让 D 的 next 指向 B，就形成了环：B -> C -> D -> B -> C -> D -> ... */
```

遍历有环链表会怎样？如何检测链表是否有环？

**思考方向**：
- 遍历有环链表的 while 循环会怎样？（cur 永远不等于 NULL）
- 如果在遍历过程中记录"访问过的节点"，能检测环吗？（但需要额外空间）
- 有没有不需要额外空间的方法？（提示：两个速度不同的指针）

---

### 参考答案

**遍历有环链表的后果**：`while (cur != NULL)` 永远不会终止——死循环。程序会卡住，CPU 占用 100%。

**检测方法1：哈希表法（需要额外空间）**

遍历时记录每个节点的地址，如果发现某个地址已经访问过，说明有环。

```c
/* 伪代码：需要额外空间存储已访问的地址 */
int has环 = 0;
/* 遍历时检查每个节点地址是否之前出现过 */
```

时间复杂度 O(n)，空间复杂度 O(n)。

**检测方法2：快慢指针法（Floyd 判圈算法，不需要额外空间）**

用两个指针，一个每次走一步（慢指针），一个每次走两步（快指针）。如果有环，快指针迟早会追上慢指针。

```c
int has_cycle(TransactionNode* head)
{
    TransactionNode* slow = head;  /* 慢指针，每次走一步 */
    TransactionNode* fast = head;  /* 快指针，每次走两步 */

    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;              /* 慢走一步 */
        fast = fast->next->next;        /* 快走两步 */

        if (slow == fast) {
            return 1;  /* 快追上慢了，有环！ */
        }
    }

    return 0;  /* 快指针到达 NULL，没环 */
}
```

**原理**：想象两个人在跑道上跑步，一个快一个慢。如果跑道是直的（无环），快的人先到终点。如果跑道是环形的，快的人迟早会套圈追上慢的人。

时间复杂度 O(n)，空间复杂度 O(1) —— 只用了两个指针变量。

这是经典的链表面试题，体现了"双指针"技巧的威力。
