## 题目1：代码副本

如果有3个程序 A、B、C 都链接了 `libaccount.a`，并且都调用了 `account_create` 函数：

1. 磁盘上有几份 `account_create` 的机器码副本？
2. 如果3个程序同时运行，内存中有几份？
3. 这带来了什么问题？

<details>
<summary>参考答案</summary>

1. 磁盘上有3份。每个程序的可执行文件中都复制了一份 `account_create` 的二进制代码。

2. 内存中有3份。每个进程加载到各自独立的地址空间，代码不共享。

3. 带来的问题：
   - 磁盘空间浪费（3份相同的代码占3倍空间）
   - 内存浪费（3个进程各占一份内存）
   - 如果库修了 bug，3个程序都要重新链接

这正是下一讲动态库要解决的核心问题：多个程序共享同一份代码。
</details>

## 题目2：ar 参数

`ar rcs libaccount.a account.o transaction.o` 命令中的 r、c、s 分别是什么含义？

1. 如果不加 `s` 会怎样？
2. 如果不加 `r` 只用 `cs` 会怎样？
3. 如何查看静态库中包含哪些目标文件？如何查看导出了哪些函数符号？

<details>
<summary>参考答案</summary>

1. 不加 `s`：归档文件不会包含符号索引表。链接器查找符号时需要线性遍历所有目标文件，效率降低。某些旧版链接器甚至会报错。`s` 相当于运行 `ranlib`，建立索引让链接器快速定位。

2. 不加 `r` 只用 `cs`：`c` 只是创建空归档，`s` 建索引。但没有 `r`，目标文件不会被实际插入到归档中，结果是一个空库。

3. 查看目标文件列表：`ar t libaccount.a`
   查看符号表：`nm libaccount.a`
   `T` 标记的符号是导出的函数（Text段），可以被外部链接。
</details>

## 题目3：链接器的提取粒度

静态链接时，链接器会把整个 `libaccount.a` 都复制进可执行文件吗？

1. 提取的粒度是什么？单个函数还是整个目标文件？
2. 如果 `account.o` 中有10个函数，主程序只用到了其中1个，会怎样？
3. 这有什么优缺点？

<details>
<summary>参考答案</summary>

1. 提取的粒度是**目标文件(.o)**，不是单个函数。链接器发现需要某个符号，就把包含该符号的整个 .o 文件复制进来。

2. 如果 `account.o` 中有10个函数，主程序只用到1个，整个 `account.o`（包含全部10个函数的代码）都会被复制进可执行文件。其他9个没用到的函数也会被包含，只是不会被调用。

3. 优点：实现简单，链接器不需要拆分目标文件内部。
   缺点：可能包含一些不需要的代码（"死代码"）。现代链接器有 `--gc-sections` 等选项可以在更细粒度上消除未使用的代码。
</details>

## 题目4：静态 vs 动态

静态库的"静态"体现在哪里？与动态库的本质区别是什么？

1. "静态"指的是什么时机？
2. 程序运行时还需要静态库文件吗？
3. 如果库有 bug 被修复了，静态链接和动态链接各需要做什么？

<details>
<summary>参考答案</summary>

1. "静态"指的是**链接时机**——在编译链接阶段就把代码固定复制进可执行文件。一旦链接完成，代码就"静态"地嵌入了。

2. 不需要。程序运行时自带了所有库代码的副本，不再依赖 libaccount.a 文件。即使删掉 .a 文件，程序照常运行。

3. 静态链接：需要重新编译库，然后重新链接所有使用了该库的程序。如果有100个程序用了这个库，就要重新链接100次。
   动态链接：只需要替换动态库文件（.dll/.so），所有使用该库的程序下次启动时自动使用新版本。无需重新编译或链接程序。
</details>

## 题目5：实践题

在本讲的 ATM 静态库代码基础上完成以下任务：

1. 新增一个 `utils.h` 和 `utils.c` 模块（包含 `print_success` 和 `print_error` 函数），将其也打包进 `libaccount.a`。
2. 修改 `main.c` 使用 `utils.h` 中的函数。
3. 用 `ar t libaccount.a` 确认库中现在包含3个目标文件。
4. 用 `nm libaccount.a` 查看3个模块导出的所有函数符号。

<details>
<summary>提示</summary>

1. 创建 `utils.h`：
```c
#ifndef UTILS_H
#define UTILS_H
void print_success(const char *op, double amount);
void print_error(const char *msg);
#endif
```

2. 创建 `utils.c` 实现，记得 `#include "utils.h"` 和 `#include <stdio.h>`

3. 修改 Makefile，在 ar 命令中加入 `utils.o`：
```makefile
ar rcs libaccount.a account.o transaction.o utils.o
```

4. `ar t` 应该输出3行：account.o、transaction.o、utils.o
   `nm` 应该显示3个 .o 段，每段有各自的 T (Text) 符号。
</details>
