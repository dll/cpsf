## 一、从运行时加载到接口抽象

### 1.1 第11讲的"痛"

第11讲我们学会了 `dlopen`/`dlsym` 运行时加载动态库，实现了插件的雏形。但有一个关键问题：

**每个插件的函数名、参数、返回值都不一样，调用方需要知道每个插件的细节。**

```c
/* 第11讲的方式：每个插件都要单独处理 */
void* handle = dlopen("deposit_plugin.so", RTLD_LAZY);
void (*deposit)(double) = dlsym(handle, "do_deposit");
deposit(500.0);

void* handle2 = dlopen("query_plugin.so", RTLD_LAZY);
double (*query)(void) = dlsym(handle2, "get_balance");
double bal = query();
/* 每个插件的函数名不同、参数不同、返回值不同！ */
```

这就像每买一个电器，就要学一种新的插头标准——有的圆头、有的扁头、有的三孔。太混乱了！

### 1.2 USB接口的启示

现实世界中，我们用 **USB接口** 解决了这个问题：不管你插的是鼠标、键盘还是U盘，电脑只管通过USB协议通信，不关心设备内部实现。

软件世界也需要"USB接口"：**定义统一的插件接口，所有插件都实现这个接口。**

```c
/* 定义统一接口：所有插件都长这样 */
typedef struct Plugin {
    int  (*init)(struct Plugin* self);
    int  (*execute)(struct Plugin* self, double amount);
    void (*cleanup)(struct Plugin* self);
} Plugin;

/* 不管是什么插件，调用方式完全一样！ */
plugin->init(plugin);
plugin->execute(plugin, 500.0);
plugin->cleanup(plugin);
```

**这就是接口抽象的核心：把多个函数指针打包成结构体接口，所有插件实现同一接口，调用方通过接口统一调用。**

## 二、函数指针回顾

### 2.1 什么是函数指针（第5讲已介绍）

函数指针就是**指向函数的指针**。函数在编译后会被加载到内存中的某个地址，函数指针变量存储的就是这个地址。

```c
/* 普通指针：指向数据 */
int a = 10;
int* p = &a;           /* p 指向变量a的地址 */

/* 函数指针：指向函数 */
int add(int a, int b) { return a + b; }
int (*fp)(int, int) = add;   /* fp 指向函数add的地址 */

/* 通过函数指针调用函数 */
int result = fp(3, 5);      /* 等价于 add(3, 5)，结果为8 */
```

### 2.2 函数指针的语法

```c
/* 声明函数指针 */
返回类型 (*指针名)(参数类型列表);

/* 示例 */
int  (*fp1)(int, int);           /* 指向 int(int,int) 的函数 */
void (*fp2)(void);               /* 指向 void(void) 的函数 */
double (*fp3)(double);           /* 指向 double(double) 的函数 */
```

**注意括号**：`int (*fp)(int, int)` 不能写成 `int *fp(int, int)`，后者是"返回int指针的函数"。

### 2.3 函数指针的用途

| 用途 | 说明 | 示例 |
|:---:|:---|:---|
| **回调函数** | 把函数作为参数传给另一个函数 | `qsort` 的比较函数 |
| **多态** | 不同对象不同行为，统一接口 | 插件接口 |
| **事件处理** | 注册事件处理函数 | GUI按钮点击 |
| **策略模式** | 运行时切换算法 | 排序策略 |

第12讲的重点：**用函数指针实现多态——插件接口的核心。**

## 三、结构体接口：C语言的"interface"

### 3.1 从数据封装到行为封装

```
第7讲：结构体打包数据
┌──────────────────┐
│  int id           │
│  char name[20]    │  ← 数据域
│  double balance   │
└──────────────────┘

第12讲：结构体打包函数指针
┌──────────────────┐
│  init()           │
│  execute()        │  ← 行为域（函数指针）
│  cleanup()        │
└──────────────────┘
```

### 3.2 Plugin接口定义

```c
/* UML 类图（ASCII文本表示）

┌─────────────────────────────────────────┐
│              «interface» Plugin          │
├─────────────────────────────────────────┤
│  name : char[32]                        │
│  version : char[16]                     │
│  description : char[64]                 │
├─────────────────────────────────────────┤
│  + init(self) : int                     │
│  + execute(self, amount) : int          │
│  + cleanup(self) : void                 │
└─────────────────────────────────────────┘
           △
           │ implements
    ┌───────┼───────┐
    │       │       │
┌───┴───┐┌──┴──┐┌──┴────┐
│存款   ││取款  ││查询   │
│插件   ││插件  ││插件   │
└───────┘└─────┘└───────┘
*/

typedef struct Plugin {
    /* 元数据：插件的基本信息 */
    char name[32];              /* 插件名称 */
    char version[16];           /* 版本号 */
    char description[64];       /* 功能描述 */

    /* 函数指针：插件的行为（接口方法） */
    int  (*init)(struct Plugin* self);       /* 初始化 */
    int  (*execute)(struct Plugin* self, double amount);  /* 执行 */
    void (*cleanup)(struct Plugin* self);    /* 清理 */

} Plugin;
```

### 3.3 为什么用 `self` 指针？

注意接口方法的第一个参数是 `struct Plugin* self`，这类似Python的 `self` 或C++的 `this`：

```c
/* C++ 版本（编译器自动传this） */
class DepositPlugin : public Plugin {
    int init() { ... }
    int execute(double amount) { ... }
};

/* C 语言版本（手动传self） */
int deposit_init(Plugin* self) {
    printf("%s", self->name);  /* 通过self访问插件数据 */
    return 0;
}
```

C语言没有编译器自动的 `this`，所以手动传递 `self` 指针，让插件方法能访问自己的数据。

### 3.4 实现插件

```c
/* 存款插件：实现 Plugin 接口 */

static int deposit_init(Plugin* self) {
    printf("[%s] 初始化完成\n", self->name);
    return 0;
}

static int deposit_execute(Plugin* self, double amount) {
    g_balance += amount;
    printf("[%s] 存入 %.2f，余额: %.2f\n",
           self->name, amount, g_balance);
    return 0;
}

static void deposit_cleanup(Plugin* self) {
    printf("[%s] 已清理\n", self->name);
}

/* 创建插件实例（填充函数指针） */
static Plugin deposit_plugin = {
    .name        = "存款",
    .version     = "1.0",
    .description = "向账户存入现金",
    .init        = deposit_init,
    .execute     = deposit_execute,
    .cleanup     = deposit_cleanup,
};
```

**关键**：存款、取款、查询三个插件功能不同，但接口统一。调用方只需要 `Plugin*` 指针就能调用任何插件。

## 四、插件链表管理

### 4.1 插件节点（衔接第8讲链表）

每加载一个插件 = 链表加一个节点：

```
head ──> [取款插件|next] ──> [存款插件|next] ──> [查询插件|next] ──> NULL
```

```c
typedef struct PluginNode {
    Plugin* plugin;             /* 指向插件接口 */
    struct PluginNode* next;     /* 指向下一个插件 */
} PluginNode;
```

**对比第8讲**：节点结构完全一样，只是数据域从 `TransactionNode` 变成了 `Plugin*`。

### 4.2 注册 = 头部插入

```c
int plugin_register(Plugin* p) {
    /* 创建新节点 */
    PluginNode* node = malloc(sizeof(PluginNode));
    node->plugin = p;

    /* 头部插入（O(1)，第8讲学过） */
    node->next = plugin_head;
    plugin_head = node;

    return 0;
}
```

### 4.3 遍历 = 统一调用（多态）

```c
/* 遍历链表，统一调用每个插件的 execute() */
void plugin_execute_all(double amount) {
    PluginNode* cur = plugin_head;
    while (cur != NULL) {
        cur->plugin->execute(cur->plugin, amount);  /* 多态调用！ */
        cur = cur->next;
    }
}
```

**这就是多态的威力**：同一个 `cur->plugin->execute()` 调用，不同插件执行不同操作——存款插件加钱，取款插件减钱，查询插件显示余额。调用方完全不需要知道这些差异。

## 五、目录扫描自动发现

### 5.1 为什么要自动发现

手动注册每个插件太麻烦：

```c
/* 手动注册：加一个插件就要改代码 */
plugin_register(&deposit_plugin);
plugin_register(&withdraw_plugin);
plugin_register(&query_plugin);
plugin_register(&new_plugin);   /* 新插件？改代码！ */
```

**自动发现**：扫描 plugins/ 目录，发现 .dll/.so 文件就自动加载注册。加插件只需把文件丢进目录，不用改代码！

### 5.2 目录扫描流程

```
┌─────────────────────────────────────────────────┐
│              plugins/ 目录                       │
├─────────────────────────────────────────────────┤
│  deposit.dll                                    │
│  withdraw.dll                                   │
│  query.dll                                      │
│  exchange_rate.dll    ← 新增插件，直接放目录!   │
└─────────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────────┐
│  扫描流程                                        │
│  1. 打开目录                                     │
│  2. 逐个读取文件名                               │
│  3. 检查后缀 .dll/.so                           │
│  4. dlopen 加载                                 │
│  5. dlsym 获取 Plugin 接口                      │
│  6. 注册到链表                                   │
│  7. 关闭目录                                     │
└─────────────────────────────────────────────────┘
```

### 5.3 跨平台目录扫描代码

```c
#ifdef _WIN32
    /* Windows: FindFirstFile / FindNextFile */
    WIN32_FIND_DATA find_data;
    HANDLE h_find = FindFirstFile("plugins\\*.dll", &find_data);
    do {
        printf("发现插件: %s\n", find_data.cFileName);
        /* 加载并注册 */
    } while (FindNextFile(h_find, &find_data));
    FindClose(h_find);
#else
    /* Linux/Mac: opendir / readdir */
    DIR* dir = opendir("plugins/");
    struct dirent* entry;
    while ((entry = readdir(dir)) != NULL) {
        if (strstr(entry->d_name, ".so")) {
            printf("发现插件: %s\n", entry->d_name);
            /* 加载并注册 */
        }
    }
    closedir(dir);
#endif
```

**实际应用**：VS Code、Eclipse、Photoshop 都是这样发现插件的——扫描固定目录 → 发现插件文件 → 加载 → 注册。

## 六、注册机制

### 6.1 注册流程

```
插件文件(.dll/.so)
    │
    ▼
  dlopen 加载
    │
    ▼
  dlsym 获取 Plugin*
    │
    ▼
  plugin_register(p)
    │
    ▼
  链表头部插入
    │
    ▼
  可以被统一调用了!
```

### 6.2 查找插件

```c
Plugin* plugin_find(const char* name) {
    PluginNode* cur = plugin_head;
    while (cur != NULL) {
        if (strcmp(cur->plugin->name, name) == 0)
            return cur->plugin;
        cur = cur->next;
    }
    return NULL;  /* 没找到 */
}
```

### 6.3 避免重复注册

注册时检查插件是否已存在：

```c
/* 遍历检查是否已注册 */
PluginNode* cur = plugin_head;
while (cur != NULL) {
    if (strcmp(cur->plugin->name, p->name) == 0) {
        printf("插件[%s]已注册，跳过\n", p->name);
        return;
    }
    cur = cur->next;
}
```

## 七、多态思想

### 7.1 什么是多态

多态（Polymorphism）：同一接口，不同实现，统一调用。

```
调用方:  plugin->execute(plugin, 500.0)
                │
        ┌───────┼───────┐
        ▼       ▼       ▼
    存款插件  取款插件  查询插件
    +500.0   -500.0   显示余额
    
    同一个调用，不同行为 = 多态
```

### 7.2 C语言实现多态的原理

```c
/* 定义接口（函数指针） */
struct Plugin {
    int (*execute)(struct Plugin* self, double amount);
};

/* 存款插件实现了 execute */
int deposit_execute(Plugin* self, double amount) {
    balance += amount;  /* 加钱 */
}

/* 取款插件实现了 execute */
int withdraw_execute(Plugin* self, double amount) {
    balance -= amount;  /* 减钱 */
}

/* 调用方：不需要知道是哪个插件！ */
void use_plugin(Plugin* p, double amount) {
    p->execute(p, amount);  /* 多态：同一个调用，不同行为 */
}
```

### 7.3 与面向对象语言的对比

| 概念 | C++/Java | C语言 |
|:---:|:---|:---|
| 接口 | `interface Plugin` | `struct Plugin` + 函数指针 |
| 实现接口 | `class DepositPlugin : Plugin` | `Plugin deposit = { .execute = deposit_execute }` |
| this指针 | 编译器自动传递 | 手动传 `self` 参数 |
| 多态调用 | `plugin->execute(500)` | `plugin->execute(plugin, 500)` |
| 继承 | `class B : public A` | 结构体嵌套 |

**这就是C语言的面向对象设计**——用结构体+函数指针模拟面向对象。

## 思考题

1. 为什么用结构体+函数指针能模拟面向对象的多态？与C++的虚函数表有什么关系？
2. 如果两个插件的 `execute()` 函数签名不同（一个需要金额，一个不需要），怎么统一到同一个接口？
3. 目录扫描自动发现插件时，如何判断一个 .dll/.so 文件是否是合法的插件？（提示：dlsym 获取特定符号）
4. 插件注册时为什么要检查重复？如果不检查会发生什么问题？

> 完整参考答案见 `思考题.md`

### 参考解答（要点）

| 题 | 一句话答案 |
|:---:|:---|
| ① | C 的"结构体 + 函数指针"与 C++ 的 vtable 本质相同：都是一张函数指针数组，区别只是 C 手动填、C++ 编译器自动生成与维护。 |
| ② | 用 `void*` 传递通用参数：存款装箱传入 `double`、查询显式忽略、转账用结构体一次传多个参数；代价是失去类型安全，需手动转型。 |
| ③ | 约定每个插件导出 `get_plugin` 作为"身份标识"，扫描时 `dlsym` 取不到就跳过；取到后再校验 `init` / `execute` / `cleanup` 是否为空。 |
| ④ | 不检查重复会导致同一插件的 `execute` 被执行多次（如重复存款）、`plugin_total` 统计偏大、列表出现重复项；目录扫描遇软链接或多线程时更易重复。 |
