# CPSF：从程序员到架构师

> **C**语言 **P**lugin **S**oftware **F**ramework —— C语言插件框架演进教程

---

## 🎯 这是什么？

这是一套**从0到1的软件架构演进教学系列**。

我们从最简单的一行C代码 `printf("Hello World")` 出发，经历 **14 讲演进**，最终抵达一个完整的**插件框架**。每一步都只引入一个新概念，每一步都解决前一阶段的真实痛点。

```
表达式 → 函数 → 模块 → 库（静态/动态）→ 运行时加载
      → 接口抽象 → 插件发现 → 插件框架 → 完整项目 + 全系列总结
```

---

## 🚀 为什么做这个？

大三学生学了C语言、面向对象、数据结构，但常常有一个困惑：

> "我会写代码，但我不知道软件是怎么从一行行代码变成一个庞大的系统的？"

这套教程就是来回答这个问题的——**让你亲眼看到软件架构的演进过程**。

## 💻 代码怎么跑起来

每一讲的 `src/` 都是**自包含**的：源码 + 构建脚本 + 构建产物 + 运行示例，
不用跳到别处找依赖，拷走一个目录就能编译。

```
<讲次目录>/src/
  ├── *.c / *.h        源码（UTF-8）
  ├── console_utf8.h   控制台 UTF-8 初始化（解决中文乱码）
  ├── build.bat        Windows 一键构建（cmd 里直接运行）
  ├── Makefile         Linux / macOS / Git Bash 构建
  ├── README.md        本讲文件清单、构建方式、演示输入
  └── 运行示例.txt     一次完整演示的真实输出
```

**Windows（cmd / PowerShell）**

```bat
cd 09_静态库\src
build.bat
```

**Linux / macOS / Git Bash**

```bash
cd 09_静态库/src
make           # 只编译
make run       # 编译并自动演示
make clean     # 清理产物
```

**一次跑完 14 讲（批量体检）**

```bash
python tools/run_check.py     # 逐讲构建 + 运行 + 检查中文是否成形
python tools/_bat_all.py      # 用真实 cmd 跑一遍所有 build.bat
python tools/verify_console.py  # 证明控制台确实切到了 UTF-8
```

## 🔤 关于中文乱码（已解决）

源码统一 **UTF-8**，而 Windows 中文版控制台默认按 **GBK(936)** 解释字节——
字节没错，是解释方式错了，于是满屏乱码：

```
欢迎使用 ATM 系统     ← 正确
娆㈣繋浣跨敤 ATM 绯荤粺   ← 同一串 UTF-8 字节被当成 GBK 读
```

解决办法分两层，两层都做了：

| 层 | 做法 |
|:---|:---|
| 程序 | 每个 `main` 开头调用 `console_utf8_init()`（见 `console_utf8.h`），内部执行 `SetConsoleOutputCP(CP_UTF8)`，把控制台切到 **65001** |
| 脚本 | `build.bat` 开头 `chcp 65001`，让脚本自己打印的中文同样不乱码 |

`tools/verify_console.py` 会把控制台强行设回 936 再运行各讲程序，
实测代码页从 **936 → 65001**，中文显示正常。
