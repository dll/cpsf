# 课件与视频统一规范（全系列 14 讲必须遵守）

> 这份规范是为解决"投影看不清、标题换行、前后不分、视频没字幕不同步"而定的。
> 所有讲次的 PPT 都必须用 `tools/ppt_kit.py` 生成，**不许手工摆形状**。

---

## 一、PPT 三条硬规矩（`audit()` 会逐页强制检查，不通过就报错）

| 编号 | 规矩 | 具体做法 |
|:---:|:---|:---|
| **R1** | 标题**绝不换行** | 标题字号按真实字体度量自动收缩（38pt→22pt），保证单行放得下 |
| **R2** | **层级分明，不许叠压** | 正文区固定在 1.56~6.28 英寸；所有容器（卡片/代码块/表格/流程）用**真实测量高度**自动撑开并依次推进 y，容器之间严禁重叠；装饰形状永远最先画（在最底层），文字永远最后画（在最上层） |
| **R3** | **对比度 ≥ 4.5:1** | 正文一律深色字压浅底（`ink` #1F2937 压 `card_*` 浅底）；需要白字压面时必须用 `solid()` 提供的深一号实色；**代码块一律深底亮字**（#0F172A + #E6EDF7），禁止浅字压浅底 |

额外自动检查：**孤儿行**（折行后最后一行只剩 ≤3 字）、文字溢出框、横向越界。

## 二、18 页标准结构（每讲都一样，方便学生形成预期）

| 页 | 内容 | 说明 |
|:---:|:---|:---|
| 1 | **封面** | 系列名 + 第N讲大标题 + 一句话定位 + 副标题点出"从一行代码到插件框架"的坐标 |
| 2 | **知识图谱位置** | ASCII 式流程图 + "你在这里"，并画出 14 讲路线（表达式→函数→模块→库→插件→框架） |
| 3 | **上一讲的"痛" → 本讲要解决什么** | 用对比表呈现"旧做法哪里不够用" |
| 4-8 | **核心内容（5 页）** | 概念、机制、代码、内存/地址图、常见错误，多用 `code()` + `card()` + `flow()` |
| 9 | **原理深入** | 最关键那一页，标题后可加 ⭐ |
| 10 | **对比与辨析** | 必含一张 Markdown 风格对照表（`kv_rows()` 或 `compare()`） |
| 11 | **ATM 实战：本讲源码** | 必须与 `src/` 下的真实代码一致（不能有出入） |
| 12 | **运行演示** | 展示**真实编译/运行输出**，并注明"片尾有演示动画" |
| 13 | **本讲在主线上的位置** ⭐ | 把"表达式 → 函数 → 模块 → 库 → 插件 → 框架"六级台阶画出来，**高亮本讲所在台阶**，并说明"本讲为终点贡献了什么"（全系列统一叙事） |
| 14 | **思考题 ①②** | 题目 + 提示，不写答案 |
| 15 | **思考题 ①② 参考解答** | 卡片式答案，左①右② |
| 16 | **思考题 ③④** | 题目 + 提示 |
| 17 | **思考题 ③④ 参考解答** | 卡片式答案 |
| 18 | **小结与预告** | 一句话总结 + 六个知识点表格 + 下一讲预告（用 `banner()`） |

## 三、讲解脚本（`video/讲解脚本.json`）

- **段数必须等于页数（18 段）**，第 i 段配第 i 页，**换页时机 = 配音段落边界**（这就是"内容与语音同步"的实现方式）。
- 每段 **110~150 字**，全片 5~9 分钟（约 18 段 × 20 秒）。
- 口语化、第一人称讲解，不要书面语编号（不要"第一，"堆砌）。
- 术语用中文读法：`printf` 读作"printf"，`\n` 读作"反斜杠n"，`-Wall` 读作"加-Wall"。
- **第 1、2 讲和第 13、14 讲用克隆音**（Voicebox），其余讲次用语音合成。

### 已经克隆过的段落不许改文案！
第 1 讲第 1~6 段、第 2 讲第 1 段（如需）的文案已经生成过克隆音，
**一旦改动就要重跑 7 分钟/段的克隆**，所以这些段落的文字必须原样保留。

## 四、`video/video_meta.json`（视频编排）

```json
{
  "fps": 12,
  "cursor":      [[0.50,0.55], ... 18 项],   // 每段鼠标落点（相对坐标）
  "click_at":    [0.55, ... 18 项],          // 每段点击发生的时间比例
  "demo_segments": [12],                     // 走"终端演示"模式的段号（一般是"运行演示"页）
  "demo_title":  "运行演示：gcc 编译 + 运行 + 退出码",
  "demo_terminal": ["$ gcc -Wall x.c -o x.exe", "$ ./x.exe", "（真实输出）", "$ echo $?", "0"],
  "demo_shots":  ["NN_讲次/src/xxx.c"]       // 右侧并列展示的源码/截图文件
}
```

- `cursor` 的落点要**落在该页真正的内容块上**（不要飘到空白处）。
- 片尾演示段用**真实程序输出**做打字动画，右侧展示真实源码文件——这就是"演示动画 + 截图展示"。

## 六、常用 API（`tools/ppt_kit.py`）

```python
from ppt_kit import *          # 常量、配色 C、solid()
prs = new_deck()
s = page(prs, '标题', '副标题', label='第N讲 XXX', page_no='auto')   # 建页 + 单行标题
y = card(s, x, y, w, '正文', title='小标题', color='orange')          # 返回 (bottom, height)
code(s, x, y, w, ['int a = 1;'], title='代码标题', size=13)           # 深底代码块
kv_rows(s, x, y, w, [('左','右')], header=('A','B'), size=14)         # 表格式列表
flow(s, x, y, w, [('① 步骤','说明')], colors=('blue','teal'))         # 箭头流程
compare(s, x, y, w, '左标题', ['左1'], '右标题', ['右1'])             # 左右对照
bullets(s, x, y, w, ['要点1', '要点2'])                              # 列表
banner(s, '一句话结论')                                              # 底部要点横幅（独立层）
footer_note(s, '结论')                                              # 正文区内的小结论条
demo_frame(s, x, y, w, h, title='运行效果', lines=[...])              # 片尾演示画框
audit(prs, 'P7')        # 质检当前页（画完立刻调用）
save(prs, path)
```

**排版要点**：所有容器都要用返回值推进 `y`（`y = card(...)[0] + 0.24`），
绝不要写死 `y += 1.3` 这类估算值——那正是旧课件叠压、溢出的根因。
